## Mathematical foundation

给定 `K: S -> C` 与 `F: S -> D`，Left Kan extension 描述较自由的延拓，
Right Kan extension 描述满足目标约束的延拓。业务分析通常只是受此概念
启发的结构检查，不等同于计算出严格的 Kan extension。

## Use conditions

仅在源场景存在已验证机制、目标场景有可核验约束，且用户需要评估迁移时
使用。不得由关键词或其他模块自动触发。

## Procedure

1. 列出源场景的对象、关系、成功条件、样本和证据。
2. 列出目标场景的对象、关系、监管、资源与不可逆约束。
3. 形成“较自由复制”和“约束优先适配”两个候选方案。
4. 逐项记录保留结构、改变结构、未知假设、反例和验证实验。
5. 使用用户数据或有来源的数据比较方案；没有数据时保留变量并做敏感性分析。
6. 给出转向、停止和退出条件。

## Output

| 结构维度 | 源场景证据 | 目标场景证据 | 候选延拓 | 失真/未知 | 验证方式 |
|---|---|---|---|---|---|

随后分别说明两个候选方案的前提、资源、可逆性和失败信号。不得使用固定
复制比例、权重、分数、风险等级、收益或时间窗口；任何数字都要附来源、
日期、地区、口径和适用范围。

## Limits

- 相似不代表因果机制可迁移。
- 样本偏差、监管差异和渠道差异可能使延拓失效。
- 方案选择是人工决策，不由阈值自动决定。
