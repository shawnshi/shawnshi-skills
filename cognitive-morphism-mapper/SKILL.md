# 跨领域结构映射

## 提取源域结构

1. 明确现实问题、目标、参与者、资源、状态、约束和反馈。
2. 用对象和关系描述结构，保留时间、方向、容量和不可逆性。
3. 把事实与解释分开。没有形式证明时使用“结构相似”或“可检验映射”，不要声称同构。

## 选择目标域

1. 选择少量有成熟机制且与源域存在结构对应的领域；数量由问题复杂度和证据覆盖决定。
2. 先读取 [references/protocols.md](references/protocols.md)。本地领域文件只有列入 [references/verified_domains.json](references/verified_domains.json) 且通过路径、来源和 SHA-256 校验后才能作为活动参考；也可以直接使用本次任务中核验的外部一手来源。
3. 需要查看领域目录时，可在不修改文件的模式下使用 [scripts/domain_manager.py](scripts/domain_manager.py)。
4. 新增领域时先用 `domain_manager.py add ...` 预览；只有用户明确授权后才加 `--apply` 创建非活动草稿。草稿补全并独立核验后，再用 `domain_manager.py promote <name>` 预览；只有用户明确授权激活后才加 `--apply`。来源、结构原语、机制前提和反例必须显式提供。

排除只提供情绪感染力、无法给出可验证机制的类比。对争议理论标明证据状态。
旧版无来源领域目录和示例不属于技能资源；需要复用其中的机制时，应重新
核验一手来源，并作为新的 `references/verified` 条目登记。固定条目数、
标题结构和示例数字不是事实、评分标准或发布门禁。

## 建立与检验映射

为每个候选映射列出：

| 源域 | 目标域 | 对应关系 | 保留的约束 | 失真点 |
|---|---|---|---|---|

然后执行：

1. 在目标域内应用具体机制或定理，写出必要前提。
2. 把推论逆映射到源域，转化为可执行动作。
3. 检查交换性：不同路径是否得到兼容结果。
4. 寻找反例、边界条件和量纲不一致。
5. 用小实验、指标或决策阈值验证映射，而不是依赖修辞。

任务包含彼此独立的多个目标域且当前环境支持时，可选用子代理并行分析；主代理使用同一源域结构和检验标准比较结果。

高级模块仅在确实能降低不确定性时按需读取 [modules/README.md](modules/README.md) 并提出使用建议。关键词命中、信息缺失或“难落地”不得自动触发模块。模块中的权重、比例、分数、时间窗口和收益数字只能来自用户数据或可核验来源，并附时间、地区、口径和敏感性；否则保留为待填变量。

## 验证分层

- 硬错误：领域文件缺失或不可读、必需来源/结构字段缺失、文件名非法、编号重复、未处理占位符。
- 软提示：映射较少、领域跨度小、章节结构不一致、相似度或反例不足、标题不够动作化。
- 人工判断：类比是否有解释力、机制能否逆映射、阈值是否合理、方案是否值得执行。关键词、字数、固定条目数和相似度分数不得作为发布阻断条件。

## 交付

输出：

1. 源域结构；
2. 目标域及选择理由；
3. 对应表和机制推演；
4. 逆映射后的方案；
5. 映射失效条件；
6. 最小验证实验；
7. 与常规方案相比新增的真实变量。

默认在当前对话交付。写入知识库、保存新领域文件或持久化洞察必须由用户明确授权并指定位置。
