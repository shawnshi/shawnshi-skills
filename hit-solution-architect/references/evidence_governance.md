# 证据与主张治理

对客户现状、产品能力、政策要求、案例效果和量化收益建立主张级追溯。不得用模型记忆、营销惯用语或空白资源补全事实。

## 1. 主张分类

| 类型 | 写法 | 可用于结论 |
| :--- | :--- | :--- |
| 已确认事实 | 标明来源、日期、适用范围和证据编号 | 可，但不超出证据边界 |
| 外部证据 | 区分官方原文、原始记录、厂商材料和二手摘要 | 按证据强度使用 |
| 项目假设 | 编号、说明理由、影响、验证动作和失效条件 | 只用于情景推演 |
| 建议 | 说明所依据的事实/假设及取舍 | 可作决策建议，不冒充事实 |
| 未知项 | 保留 `{{FIELD}}`，列出取证人、方法和截止时间 | 不得进入可提交结论 |

## 2. 主张台账

| `{{CLAIM_ID}}` | `{{CLAIM}}` | `{{FACT/EVIDENCE/ASSUMPTION/RECOMMENDATION/UNKNOWN}}` | `{{EVIDENCE_ID}}` | `{{FILE_PAGE_CLAUSE_OR_URL}}` | `{{DATE}}` | `{{SCOPE}}` | `{{A/B/C}}` | `{{LIMITATION}}` | `{{STATUS}}` |

本技能统一使用以下证据强度；信创工作表引用本定义，同一证据 ID 不因转表而改级：

- A：当前正式的官方文件、客户授权原始记录或可重复的项目测试。
- B：官方解释、经确认的会议纪要或条件清晰的厂商技术材料。
- C：厂商宣传、历史案例或二手摘要；只能形成待验证项。

## 3. 量化与时效

- 每个实际数字记录数值/区间、单位、来源、资料日期、地区/机构范围和计算口径。
- “无来源”“来源缺失”“来源待补”、空来源字段或来源占位符均不是有效来源；其他主张的邻近来源不能覆盖本条明确缺证据状态。自动门在工作稿、审阅稿报告缺来源警告，在可提交稿报错；来源标记检查不证明来源真实或支持该主张，仍需人工核验。
- 政策、评价标准、信创目录、产品版本及兼容性在使用时重新核验，不把历史资料当作当前事实。
- 临床效果、性能提升和成本节省需有适用环境、基线、测量方法和限制；否则仅列为待验证假设。

## 4. 冲突处理与发布门禁

1. 并列记录冲突来源，不在无证据时自行择边。
2. 优先检查对象、版本、日期、地区和口径是否一致。
3. 无法消解时标记冲突，说明对决策的影响和需要的追加取证。
4. 可提交稿中不得保留影响核心结论的未知项、无来源数字、未核验产品能力或未解决证据冲突。

## 5. 内部知识源取证

A 级“客户授权原始记录”与 B 级“厂商技术材料”的常见取证渠道是内部知识源：PreMind 提供我方原件与结构化评级，Vector Lake 提供既往方案与已登记的决策节点。取证时遵守：

- **现状与基线**：客户存量方案、集成与架构现状、评级等级取自原件；等级表述使用结构化评级数据，不用网络转述。
- **产品能力**：我方材料按其材料性质定级；**厂商自述不因来自内部而升为 A**，仍受版本、适用环境与“需配置/需开发/未验证/暂不支持”约束。
- **迁移与回退**：历史割接先例取自既往方案原件，注明其适用的系统规模、年份与地区。
- **评审一致性**：与已登记决策节点比对；发现与既往判断冲突时并列记录，不单方择边。
- 台账 `EVIDENCE_ID` / `来源定位` 记录原件引用或节点标识；`as_of` 用材料自身日期，历史材料不当作当前事实。
- 取证工具：原件与评级用 `lan-mcp-1441_search_knowledge` / `get_source_excerpt` 与 `lan-mcp-1441_query_ratings`；既往方案与已登记决策节点用 `vector-lake-mcp_search_vector_lake`。
- 患者数据不得作为检索输入；密级与外部使用授权仍按输入合同四轴判定，不因来源是内部而放宽。
- 内部来源不可用时报告缺口，不得写成“无数据”。
