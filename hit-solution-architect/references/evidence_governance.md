# 证据与主张治理

对客户现状、产品能力、政策要求、案例效果和量化收益建立主张级追溯。不得用模型记忆、营销惯用语或空白资源补全事实。

## 1. 主张分类

| 类型 | 写法 | 可用于结论 |
| :--- | :--- | :--- |
| 已确认事实 | 标明来源、日期、适用范围和证据编号 | 可，但不超出证据边界 |
| 外部证据 | 区分官方原文、原始记录、厂商材料和二手摘要 | 按证据强度使用 |
| 项目假设 | 编号、说明理由、影响、验证动作和失效条件 | 只用于情景推演 |
| 建议 | 说明所依据的事实/假设及取舍 | 可作决策建议，不冒充事实 |
| 未知项 | 保留 `{{FIELD}}`，列出取证人、方法和截止时间 | 不得进入可提交结论 |

建议的证据强度：

- A：当前正式的官方文件、客户授权原始记录或可重复的项目测试。
- B：官方解释、经确认的会议纪要或条件清晰的厂商技术材料。
- C：厂商宣传、历史案例或二手摘要；只能形成待验证项。

## 3. 量化与时效

- 每个实际数字记录数值/区间、单位、来源、资料日期、地区/机构范围和计算口径。
- 政策、评价标准、信创目录、产品版本及兼容性在使用时重新核验，不把历史资料当作当前事实。
- 临床效果、性能提升和成本节省需有适用环境、基线、测量方法和限制；否则仅列为待验证假设。

## 4. 冲突处理与发布门禁

1. 并列记录冲突来源，不在无证据时自行择边。
2. 优先检查对象、版本、日期、地区和口径是否一致。
3. 无法消解时标记冲突，说明对决策的影响和需要的追加取证。
4. 可提交稿中不得保留影响核心结论的未知项、无来源数字、未核验产品能力或未解决证据冲突。
