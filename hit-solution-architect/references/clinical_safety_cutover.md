# 临床安全与生产切换门禁

当方案会改变患者身份、医嘱、用药、检验检查结果、临床文书、手术/重症流程、临床 AI 输出或核心诊疗系统连续性时，启用本门禁。这是项目安全检查，不替代医院制度、法定责任或专业临床判断。

## 1. 启动前必须确认

- 适用地区、院区、科室、患者范围和业务时段。
- 材料密级、患者数据授权/脱敏状态及数据流向。
- 受影响的临床决策、业务连续性、故障降级方式和最大可容忍中断。
- 临床责任人、技术责任人、数据责任人、安全/合规责任人和切换指挥权。

缺少上述信息时可继续形成工作稿，不得给出可上线或可切换结论。

## 2. 切换准入证据

| gate_id | 必须证据 | 未满足处理 |
| :--- | :--- | :--- |
| G1 范围与基线 | 范围冻结、存量版本、业务量与异常基线 | 暂停决策 |
| G2 数据一致性 | 迁移规则、完整性/准确性/时序核对结果、差异处置记录 | 暂停切换 |
| G3 业务与接口 | 端到端场景、第三方接口、权限、审计及关键异常测试 | 暂停切换 |
| G4 韧性与恢复 | 容量/性能、故障转移、备份恢复、RTO/RPO 测试及环境记录 | 暂停切换 |
| G5 降级与回退 | 人工降级流程、回退触发条件、数据回补、演练记录和时间窗口 | 暂停切换 |
| G6 组织就绪 | 培训、值守、通讯录、指挥中心、升级路径和临床现场支持 | 暂停切换 |
| G7 批准与剩余风险 | 临床、技术、数据及安全/合规责任人签字；剩余风险有明确承接人 | 不得作出“继续实施”决定 |

阈值不使用默认经验数。将 `{{THRESHOLD}}`、`{{RTO}}`、`{{RPO}}`、`{{DOWNTIME_WINDOW}}` 与其客户批准证据写入方案。

## 3. 临床数据核对最小范围

按实际系统裁剪，至少评估：患者主索引与就诊关系、过敏史、诊断、医嘱及状态、药品与剂量、检验检查结果及危急值、手术/麻醉记录、临床文书版本、费用与医保关键状态。为每类对象明确总量、抽样/全量方法、容差、差异责任人和处置证据。

## 4. 继续实施/暂停实施决策

- 所有适用门禁达标且剩余风险被具名承接后，才可建议继续实施。
- 任一核心门禁失败、关键差异未闭环或无权人员签字时，建议暂停实施。
- 切换后按 `{{HYPERCARE_PERIOD}}` 监测关键业务、数据、接口、性能和安全指标；达到预先批准的回退条件时，由指定决策人启动回退。

## 5. 临床 AI 补充检查

确认用途、输入数据、适用人群、输出展示、人工复核、可忽略/可纠正机制、版本变更、本地验证、偏差与漂移监测、异常停用及责任边界。没有项目证据时，不宣称改善患者结局或替代临床判断。
