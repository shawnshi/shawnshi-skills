# 医疗数字化方案模块化结构

本文件是结构菜单，不是固定目录。先在 `delivery_profiles.md` 选择交付模式，再按 `scene_routing.md` 载入适用模块。不因“看起来完整”而生成无关的迁移、TCO、产品或合规章节。

## 1. 交付状态

| 状态 | 允许 | 必须满足 | 对外使用 |
| :--- | :--- | :--- | :--- |
| `draft` 工作稿 | 保留 `{{FIELD}}`、编号假设和未知项 | 标明证据边界、取证动作和阻断项 | 不作客户承诺或上线依据 |
| `review` 审阅稿 | 保留不影响主结论的待确认项 | 结构完整，未知项台账、证据台账和审阅责任明确 | 仅用于指定评审范围 |
| `release` 可提交稿 | 仅保留明确标注的排除项、已接受剩余风险和后续行动 | 无未处理占位符、无无来源数字、无未核验产品/政策主张，适用责任人已复核 | 可在已批准范围内提交 |

文档首页或文件头必须记录：交付模式、状态、决策问题、受众、适用地区/机构、范围与排除项、资料截止日期、版本和审阅人。

## 2. 核心模块

核心模块的详细程度由交付模式决定。架构快评可合并成短章，详细架构应展开为可测试设计。

### A. 决策摘要与范围

- 本次必须做出的决策、建议方向和不采用该方向的后果。
- 已确认事实、关键假设、信息缺口、范围与排除项。
- 主要替代方案、取舍、待决定事项和决策期限。

### B. 现状、证据与约束

- 业务流程、系统边界、接口、数据流、部署、运维和供应商责任。
- 基线指标、已确认问题、单点、技术债和证据局限。
- 预算、周期、人员、窗口、采购、安全、隐私、标准与验收约束。

### C. 目标能力与架构

- 业务结果/风险控制目标、对应能力和成功条件。
- 应用、数据、集成、技术、安全和部署边界；组件责任和关键依赖。
- 使用 `architecture_traceability.md` 追溯业务、能力、系统、数据、接口、NFR 和验收。

### D. 数据、互操作与安全

- 数据对象、权威源、标准、质量、血缘、同步、保留和销毁。
- 接口发起/接收方、契约版本、幂等、超时/重试、错误处理、监控与责任。
- 身份、最小权限、职责分离、加密、密钥、审计、脱敏和数据流向。

### E. 非功能、韧性与运维

- 容量、峰值并发、延迟、可用性、扩展、RTO/RPO、备份恢复和故障降级。
- 每个指标记录单位、工作负载/环境、测试方法、阈值来源和责任人。
- 日志、指标、追踪、告警、值守、升级、发布、配置和服务交接。

### F. 交付、验收与治理

- 工作包、依赖、进入/退出条件、交付证据和责任边界。
- 功能、接口、数据、性能、安全、容灾和运维验收。
- 变更、偏离、例外/ADR、风险升级、业务/技术签字和证据留存。

### G. 风险、替代方案与待决定事项

- 风险触发条件、影响、缓解、剩余风险、owner 和时限。
- 至少说明保持现状、推荐方案及其主要替代方案的取舍。
- 待决定事项标明决策人、需要证据、截止时间和不决策的影响。

## 3. 条件模块

| 模块 | 加载条件 | 必须包含 |
| :--- | :--- | :--- |
| 迁移、切换与回退 | 存量系统替换、数据搬迁、生产切换、院区合并或关键版本跨越 | 迁移对象、映射/清洗、核对、双轨/灰度、降级、回退、停机窗口、进入/退出条件和责任人；影响临床时应用 `clinical_safety_cutover.md` |
| 技术 TCO/ROI 输入 | 明确的技术方案成本比较或 TCO 问题；需要 ROI 变量时与战略决策任务协同 | 基准反事实、边界、增量现金流、符号口径、NPV/回收期、风险调整、敏感性和双计数检查；本技能不单独得出投资优先级或预算推荐 |
| 产品适配与采购 | 指定产品、厂商、采购参数或招投标偏离 | 中立需求、精确版本、证据日期、部署/许可条件、偏离、PoC 及承诺边界；无当前证据时不声称具体能力 |
| 技术蓝图与架构演进 | 业务战略与投资方向已定，需要形成分期技术路径 | 技术基线、目标技术能力、技术工作包、架构依赖、阶段技术准入/退出门和架构治理；不重做业务战略、投资组合优先级和效益兑现责任 |
| 架构评审 | 评审、准入或方案审查 | 使用 `architecture_review_scorecard.md`，输出门禁、评分、问题分级、整改/例外及通过判定 |
| AI 设计 | 使用模型或生成式 AI | 用途、数据、版本、人工监督、本地验证、偏差/漂移、失效降级和责任边界 |
| 跨机构/跨境 | 区域协同、国际医疗、数据出境或外部科研合作 | 各方角色、适用地区、数据分类与流向、合法依据待核验项、最小必要、审计和异常升级 |

## 4. 数字和变量最小记录

| 字段 | 要求 |
| :--- | :--- |
| value_or_range | 数值或区间；未知时使用 `{{FIELD}}` |
| unit | 币种、比例、时间或业务单位 |
| source_and_locator | 来源及文件/页码/条款/记录定位 |
| as_of | 资料、版本或测量日期 |
| region_and_scope | 适用地区、机构、环境或人群 |
| method | 计算、抽样或测试口径 |
| assumption_id | 假设项的编号、理由和失效条件 |
| sensitivity | 变化范围及对结论的影响 |

## 5. 发布前检查

- 结构与选定的交付模式一致，条件模块有明确触发理由。
- 业务需求、能力、系统、数据、接口、NFR 和验收可追溯。
- 产品、政策、案例、客户现状和量化数字的证据强度与表述相匹配。
- 影响临床或生产切换时，已完成安全、数据核对、降级、回退和签字检查。
- 审阅稿和可提交稿明确区分自动检查结果与人工复核结论。
