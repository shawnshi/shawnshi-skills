# 医疗数字化方案结构参考

本模板提供可裁剪的内容模块，不规定固定页数，也不要求每个项目覆盖全部模块。应以用户目标、项目范围和已确认约束决定结构；信创、旧系统迁移、临床场景或区域监管仅在与项目有关时纳入。

## 1. 决策摘要

- 决策问题与本次方案范围
- 已确认事实、关键假设和信息缺口
- 推荐方向、主要替代方案与待决定事项

## 2. 现状与约束

- 业务流程、系统边界、数据流和接口
- 基础设施、运维模式和责任边界
- 适用的预算、周期、合规、停机窗口和验收约束
- 证据来源、资料日期和仍需客户确认的内容

## 3. 目标能力与架构

- 业务能力及其对应的问题或风险控制目标
- 应用、数据、技术和安全边界
- 数据权威源、接口标准、部署责任和关键依赖
- 可用性、性能、扩展、互操作、隐私、容灾和可维护性要求

## 4. 迁移、回退与验收

- 试点与分阶段范围
- 数据迁移、双轨运行或灰度切换条件
- 停机窗口、回退触发条件和恢复步骤
- 验收指标、测试方法、责任人和证据留存

不预设阶段时长或停机容忍度。若客户尚未确认，使用 `[PHASE_DURATION]`、`[DOWNTIME_WINDOW]` 等待填变量。

## 5. 成本与收益模型

- CAPEX、OPEX、迁移、培训、停机和退役成本
- 可核验的收益变量、计算公式和时间范围
- 悲观、基准、乐观场景及敏感性分析
- 无法取得客户数据时只输出变量表和取数计划，不计算确定性 ROI

每个数字使用以下最小记录：

| 字段 | 要求 |
| :--- | :--- |
| `value_or_range` | 数值或区间；未知则标记 `[待客户确认]` |
| `unit` | 币种、比例、时间或业务单位 |
| `source` | 客户材料、合同、公开文件或测量记录 |
| `as_of` | 资料或测量日期 |
| `region` | 适用国家、地区或机构范围 |
| `assumption_id` | 仅假设项填写，便于追踪 |
| `sensitivity` | 变化范围及其对结果的影响 |

## 6. 厂商与采购要求

- 只比较公开、可核验且与项目需求相关的能力
- 记录产品版本、部署条件、验证日期和证据强度
- 将采购要求写成中立、可测试的功能或非功能指标
- 不设计排他参数，不推断个人偏好、私人关系或未公开动机

## 7. 风险与待决定事项

- 单点故障、迁移、锁定、合规和承诺风险
- 风险触发条件、缓解动作、责任人和剩余风险
- 信息缺口、取证动作和最终决策门槛

## 质量检查分层

| 层级 | 示例 | 处理方式 |
| :--- | :--- | :--- |
| 确定性硬检查 | 缺必填字段、编号错误、未处理占位符、来源字段缺失、公式不可计算 | 阻断交付 |
| 启发式软提示 | 语言可能空泛、章节可能重叠、量化信息可能不足、标题不够动作化 | 提示修改，不自动阻断 |
| 人工判断 | 方案逻辑、产品适配、承诺风险、项目可执行性 | 由负责人复核 |

描述性标题在技术文档中可以是准确选择；动作化标题不是普遍硬要求。并非每个陈述都必须包含数字，但任何实际数字都必须可追溯。
