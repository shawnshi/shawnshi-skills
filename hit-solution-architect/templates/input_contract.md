## 3. 安全与证据检查

| 问题 | 结果 | 动作 |
| :--- | :--- | :--- |
| 患者数据状态 | `{{NONE/DEIDENTIFIED/IDENTIFIABLE/UNKNOWN}}` | `NONE` 仅表示无患者数据，不证明公开、任务使用或外传获准；可识别或状态未知的患者数据不得外传，先取得最小必要的合规版本 |
| 材料密级 | `{{PUBLIC/INTERNAL/CONFIDENTIAL/UNKNOWN}}` | 内部、机密或密级未知的材料按受限材料处理；公开属性不替代任务或外部使用授权 |

| 外部使用授权 | `{{AUTHORIZED/UNAUTHORIZED/UNKNOWN}}`；获准渠道、接收方与范围 `{{EXTERNAL_AUTH_SCOPE}}` | 未授权或授权不明时不得发送给外部工具、外部检索或子代理；已授权仍须核对密级、脱敏、渠道和最小必要范围 |

四轴独立记录，任何一轴的放行状态不能覆盖另一轴的限制。例如：无患者数据的机密拓扑，即使获准用于当前任务，未获外部使用授权也只能在批准的处理边界内使用，不得外部检索或委派。四轴不是自动授权器，仍执行入口的医疗安全与数据门禁。

## 5. 跨技能最小交接

战略转架构、架构转写作均保留下列六字段；在现有交接材料中记录，不另建状态系统。

| 字段 | 必须保留的内容 |
| :--- | :--- |
| 决策与范围 ID | 原 ID、来源、技术边界与排除项 |
| 证据与来源 | 证据 ID、来源定位、日期、适用范围、证据强度及冲突 |

| 成熟度与授权边界 | 原成熟度、真实批准记录及范围；患者数据、密级、任务和外部使用四轴状态 |

战略批准不继承为架构发布或实施批准。写作只能在获准范围内调整表达，不改变技术事实、数字口径、证据强度或批准状态；交接、保存、自动检查均不授权发布、外传或实施。

## 使用规则

- 只有决策问题、受众和交付模式缺失且无法从用户请求判断时，才优先追问。
- 可推断项必须明确标为假设，不转写为客户事实。
- 工作稿可保留 `{{FIELD}}`；审阅稿必须附未知项台账；可提交稿不得保留影响结论的未知项。
