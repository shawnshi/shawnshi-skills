# 标题写法对比示例

动作化标题有助于高管材料直接表达判断，但不是所有文档的硬要求。接口规范、数据字典、测试报告和法规说明通常更适合准确的描述性标题。

下表中的目标和周期均为写法占位符，不是业务事实。

| # | 描述性标题 | 可选的判断型标题 |
| :---: | :--- | :--- |
| 1 | 系统建设目标 | 以 `{{MATURITY_TARGET}}` 为验收锚点，重构临床数据治理责任 |
| 2 | 数据平台规划 | 统一患者时间轴，减少跨科室数据断点 |
| 3 | 医保管理系统 | 以已确认的病种成本口径支持事中审核 |
| 4 | 信息化升级方案 | 从存量系统约束出发确定可迁移的目标架构 |
| 5 | 移动医疗平台 | 将病区文书时间从 `{{BASELINE}}` 调整至 `{{TARGET}}` |
| 6 | 患者服务优化 | 将已测量的院内等待时间从 `{{BASELINE}}` 调整至 `{{TARGET}}` |
| 7 | 安全合规建设 | 将适用的合规要求映射到访问、审计和留痕控制 |
| 8 | 系统集成方案 | 以可测试的接口契约降低第三方联调不确定性 |
| 9 | 实施计划 | 在 `{{PARALLEL_RUN_DAYS}}` 天双轨期内验证切换与回退条件 |
| 10 | 技术成本分析 | 基于 `{{ANALYSIS_PERIOD}}` 的成本边界和敏感性区间比较技术方案 |

## 可选构造方式

`动作或判断 + 业务对象 + 证据支持的目标或约束`

数字只在具有数值、单位、来源、资料日期和适用范围时写入标题。缺少数据时保留变量，不用示例比例替代。

## 人工复核

- 标题是否准确反映本节内容？
- 判断型标题是否有正文证据支持？
- 技术文档使用描述性标题是否更精确？
- 数字是否能追溯到项目证据或明确编号的假设？
