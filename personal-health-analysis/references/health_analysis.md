# Garmin 健康指标解释边界

本资料用于解释用户已经授权读取的 Garmin 可穿戴设备数据。它不是临床指南，不提供诊断、处方、补剂剂量、训练处方或日程命令。

## 1. 解释优先级

1. 先说明设备、数据日期、观察窗口、缺失率和佩戴空档。
2. 优先比较同一用户、同一设备和相近生活情境下的个人基线。
3. 将设备原始值、厂商派生指标、脚本计算值和分析推断分开。
4. 单日变化只描述为观察；连续变化也只形成待核验信号。
5. 用户症状、病史、药物、旅行、饮酒、感染、海拔、月经周期和设备固件变化都可能造成混杂。
6. 缺失观测保持 `null`，并披露请求天数、有效天数、覆盖率和组件错误；不得把缺失或失败写成 0。
7. 跨指标比较只使用同一观测日期的数据；HRV 与静息心率的基线变化至少需要 21 个同日历史样本。零方差基线只报告绝对变化并标记不可分类。

## 2. 指标可以支持什么

### HRV

- 可以描述夜间 HRV、Garmin 状态以及相对个人基线的变化。
- 不能仅凭 HRV 判断感染、心血管疾病、过度训练、精神压力或认知能力。
- 不跨设备直接比较绝对值；设备或算法变更要作为数据断点。

### 静息心率

- 可以描述静息心率相对个人基线的变化。
- 不能把变化直接归因为感染、脱水、压力或训练负荷。
- 与明显症状同时出现或持续异常时，建议用户携带原始数据咨询合格医疗人员。

### 睡眠

- 可以报告总时长、作息一致性、设备睡眠评分和睡眠阶段估计。
- 消费级设备的睡眠阶段是算法估计，不能据此诊断睡眠障碍。
- 不把某个深睡或 REM 百分比写成普遍适用的合格线。

### 压力、Body Battery 与准备度

- Garmin 压力和 Body Battery 是厂商派生指标，只能按厂商定义描述。
- 若本地脚本生成准备度指数，必须同时披露算法、输入、配置来源和不确定性。
- 没有启用且具备来源元数据的配置时，不生成准备度分数、红黄绿灯或行动等级。
- 分数不得决定用户是否训练、开会、编码、投资或作出其他重要决策。

### 训练负荷、CTL、ATL 与 TSB

- 这些指标依赖具体负荷定义、时间常数、运动类型和训练背景。
- 本技能不得把自定义“摩擦负荷”当成经过验证的运动训练负荷。
- 没有启用且具备来源元数据的配置时，只展示 Garmin 原始训练字段，不计算或解释 CTL、ATL、TSB 分区。

### 呼吸率、血氧、体成分与环境数据

- 可以报告设备记录值及个人趋势。
- 不用单个阈值宣布呼吸疾病、缺氧、脱水或体成分异常。
- BMI 只有在身高和体重均来自用户或设备数据时才计算；不得填入估计身高。

## 3. 阈值和评分配置

`resources/clinical_guidelines.json` 是可选的方法配置，不是临床事实库。

任何启用的阈值或评分必须包含：

- `source_type`
- 可定位的 `source`
- `published_at`
- `retrieved_at`
- `region`
- `population`
- `intended_use`

字段缺失、配置未启用或适用人群不匹配时，脚本必须退化为 `unclassified_observation_only`，不得使用硬编码回退值。

用户或临床人员提供的阈值要标为 `user_supplied` 或 `clinician_supplied`；本地方法假设要标为 `method_assumption`，并明确它未经临床验证。

## 4. 建议语言

允许：

- “最近几天相对个人基线出现变化，可结合症状、训练和设备佩戴情况继续观察。”
- “如果你主观感觉恢复不足，可以考虑降低强度或安排休息；是否调整由你决定。”
- “若变化持续、伴随明显症状或影响日常生活，建议咨询合格医疗人员。”

不允许：

- 宣布感染、炎症、免疫崩溃、激素失调或认知宕机。
- 推荐镁、茶氨酸、维生素、锌或其他药物、补剂和剂量。
- 要求用户强制训练、停止训练、取消会议、推迟闹钟或禁止决策。
- 把 Garmin 分数称为临床级证据、疾病风险概率或职业表现预测。

## 5. 报告结构

1. 数据范围、来源、设备和新鲜度
2. 可直接观察的指标
3. 与个人基线的描述性比较
4. 可能的混杂因素和未知项
5. 可选的一般性自我照护建议
6. 需要医疗升级处理的症状或持续变化

## 6. 医疗升级边界

- 胸痛、严重呼吸困难、晕厥、疑似中风或用户描述的其他急症信号：停止常规分析，建议立即联系当地急救服务。
- 持续异常、明显症状或影响生活的变化：建议咨询合格医疗人员，并携带原始数据。
- 没有急症或持续症状时，不因可穿戴设备单项变化制造恐慌。
