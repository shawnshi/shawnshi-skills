# 运行时兼容性与证据边界

## 普通分析

- 本地分析需要 Python 3.11+、pandas 3.0.6；实时读取需要 Python 3.12+、garminconnect 0.3.17。以同一解释器的运行预检为准，不自动切换或安装。
- 预检分别返回包版本、模块定位结果和实际导入/API 符号探针。只有全部通过才返回 `RUNTIME_READY`；模块定位成功不称为可导入。
- 导入探针在同一解释器的短期子进程中运行，移除环境中的 GARTH/GARMIN 设置，不创建客户端、不恢复令牌、不请求健康数据。它不是网络沙盒，也不能替代真实服务可用性检查。
- 实时认证与洞察共用稳定的令牌快照检查和 Garmin 直连规则。洞察只做内存令牌恢复，不初始化账户 Profile/settings，也不持久化刷新后的令牌。SDK 和 HTTP 层重试均关闭；出现限流或传输失败后停止，不另造重试链。
- `insight_cn` 在解析参数后统一进入 bounded 实现；`--source local`、`--source=local`、省略本地默认来源及选项位于位置参数之前均沿同一入口。未显式授予健康读取或联网权限时仍失败关闭。上层显式 `--state-output` 仍沿既有最小状态写入器保存，不保存分析正文，默认拒绝覆盖；普通调用不新增任何写入。

## GarminDB 同步：未解除的兼容性例外

已检查的当前 runner 组合为 `garmindb==3.9.0` 与 `garminconnect==0.3.17`。前者的上游元数据要求 `garminconnect==0.3.11`，因此 `pip check` 存在真实依赖冲突。

- 固定版本、源码哈希、合成测试或计划绑定不证明这个组合完成了真实下载/导入。
- 本次技能维护不安装、降级或改写 runner；也不宣称上游兼容性已获修复或独立批准。
- 在投入新一轮真实同步前，需要在明确授权的范围内验证该组合的真实链路与恢复路径，或选择依赖声明一致且通过验收的 runner 组合。源码里的版本检查仍只是已有 runner 识别门，不是依赖一致性检查。
- 相关验证不能借机读取无关健康历史、登录、改写令牌或下载轨迹；每项动作继续执行自己的授权门。

## Pi 与 Codex 触发配置

- Pi 的发现及自动匹配以 `SKILL.md` 为准；本技能保留当前 Pi 自动匹配行为，显式设置 `disable-model-invocation: false`，不因格式维护改变用户调用方式。
- `agents/openai.yaml` 属于 Codex 配置，里面的 `allow_implicit_invocation: false` 不作为 Pi 权限控制。需要改变 Pi 为仅显式 `/skill:personal-health-analysis` 调用时，再按用户指定修改 frontmatter，不能假定另一运行时的策略已在 Pi 生效。
- 自动匹配只决定是否加载技能说明，不产生读取健康数据、联网、同步、保存或分享授权。
