# 数字健康周报：研究与模板填充说明

本文件是操作说明，不是报告正文。入口、交付模式和保存授权以 [SKILL.md](../SKILL.md) 为准；这里只补充研究规则与填充细则。assets 按检索面选读，合成示例不作事实来源。

## 时间与纳入

统一按报告时区解释日期，保留发布日期、事件日期、访问日期；政策另记生效日，未公开时如实说明。

- **发布日期**是原文首次公开或实质修订时间，不是转载/网页维护日期。**事件日期**是本行实际动作的时间，用于纳入。**生效日期**是开始适用的时间，不能与发布混写。
- 窗口从起始日零点到 `min(周期结束日当日结束, cutoff)`，即严格早于结束日次日零点且不晚于 cutoff。同日材料仅有日期不能证明早于 cutoff；时间无法确认时列待核。
- 上月发布、本周生效：本期可列“生效”；本周发布、下月生效：本期列“发布”，未来生效日仅作影响条件。发布、实施、实质版本更新可分别成事件，同一动作的转载/摘要/镜像去重。
- 历史补刊不得扩大事件窗口。后发材料可以追溯核验当期动作，但须保留两种日期；后来分析与后续结果标“补刊时可见的背景”，不伪装为当周已知信息。
- 区间两端均须在窗口内，不截断日期凑数。旧事件在其他章节标“背景”，不进关键事件表。全球信号须解释中国监管、采购、工作流及数据条件下的可迁移性。

## 有界检索

预算是全任务设计上限，不是速度承诺，不按 asset、并行操作或检索面重复分配。

1. 选择与决策相关的政策、战略/市场、技术检索面；跨行业仅在有机制对应时使用。首轮总计 **2–4 个互补查询**，每查询筛选前 **10 条结果**，摘要只用于选候选。
2. 按原文件、主体、动作、版本和事件日期去重。最多 **8 个候选**，优先合规期限及采购/运营/架构影响，不按热度或机构名气排序。
3. 原文访问最多 **8 次尝试**，含失败、重试、独立复核及背景抓取；先解决关键原始依据。仅关键日期、原文或高影响复核有缺口时再补检一轮，最多 **2 个查询**，仍共享上述上限。同一失败入口最多重试一次，不换关键词绕过预算。
4. 独立操作并发最多 **3**，不强制子代理；复用本次已读材料，不新增长期缓存。用户明确扩大范围后可另约有限预算。
5. 所选检索面完成且关键证据解决、补检后仅剩重复/低相关项、关键预算用尽或能力受阻时收束。记录查询数、访问尝试数、覆盖面、未完成项及停止原因，不循环追搜。

**空结果不等于错误**：有效完成所选查询及必要筛选且确无合格事件，才用空结果标记，同时披露覆盖限制。断网、访问拒绝、日期待核、预算耗尽而关键核验未完成，都不能写成“零事件”；交付已确认内容的预览，正式交付 BLOCKED。个别候选被有依据地排除不等于全任务失败。

## 证据与决策

证据强度针对具体主张，不按品牌打分，不替代临床证据分级：

- **高**：可访问原始依据，日期/版本/范围清楚，有支持该主张的独立证据，无未解决实质冲突。
- **中**：原文可核实但单一来源，或样本/外部验证有限；可报告发布等事实及来源观点，不单独支持高影响效果判断。
- **低**：二手、厂商效果宣称、预印本初步结果、摘要或关键细节不足；仅作来源主张/待验证信号。动作和日期无法核实则不进正式事件表。

厂商公告能证明“宣布某版本”，不能证明疗效或收益；预印本注明未同行评审及研究类型，不转写为临床建议。转载或共同依赖同一数据/利益主体的材料不算独立复核，付费摘要不冒充全文。

**高影响结论**涉及临床安全、合规、重大预算或不可逆架构。效果、因果和外推判断须原始依据加独立证据；不足则降为待核假设。法规原文可直接证明明确条款、对象和期限，不必寻找重复发布的第二来源；解释或具体适用性有争议时请合规负责人确认。两条 URL 本身不等于验证。

事实、来源主张、分析、假设分层。冲突先查版本、地区、样本、指标与利益关系；不能裁决则并列降置信度，不多数投票，不强凑反共识。建议动作给来源依据、适用条件、验证/停止节点；证据不足时建议核验而非部署，不虚构 ROI 或规模。

## 正式模板填充

使用 [template.md](template.md)，替换全部方括号占位符；无适用内容说明原因，可选分歧节无冲突则省略。教学句、合成内容、代码或 HTML 注释不能充当正式结果。

- 首个二级标题前各一次未加粗的独立字段：`报告周期：YYYY-MM-DD 至 YYYY-MM-DD`、`出刊日期：YYYY-MM-DD`、`生成时点：带偏移ISO-8601`、`报告时区：Asia/Shanghai`。其他有效 IANA 时区须与 CLI 同名；生成时点允许不同偏移表示同一 cutoff。
- 标题同月如 `# 数字健康周报｜2000年1月3日—9日`，跨月如 `# 数字健康周报｜2000年1月31日—2月6日`，跨年如 `# 数字健康周报｜1999年12月27日—2000年1月2日`。日期与参数同步；未完结声明在头部，完整周期说明覆盖范围。
- 唯一 `## 关键事件与来源` 内每行严格六列非空且遵循模板表头。日期优先 ISO，区间用 `YYYY-MM-DD 至 YYYY-MM-DD`。单元格竖线写 `\|`；来源列给直接 `http(s)` URL 或 `[原文](https://…)`，不能仅给 S1、DOI 或搜索结果页。
- 无事件时删示例行，仅在本节独立一行写一次 `本周期未发现符合纳入标准的事件`，可留表头，不与事件行并存；必须满足前述有效检索条件。
- 来源清单逐项对应事件，保留发布/事件/访问日期；未披露字段写明。其他章节可用来源编号。
- 代码围栏和缩进代码不提供有效结构，正式文件不保留 HTML 注释。校验器检查日期、六列、非空、URL 形式及已知占位符；真实性、可访问性、同日时刻、证据强度和结论仍人工核验。

旧目标只核身份，不强制迁移正文；身份不明不自动重写。回到入口执行结构验证及 [共享归档门禁](../../shared/references/report_archive.md)。早期只读能力检查不证明 DACL/AccessCheck 可用，失败不授权提权或复制回退；预览请求不写私有草稿，已有草稿与恢复证据按共享契约保留。
