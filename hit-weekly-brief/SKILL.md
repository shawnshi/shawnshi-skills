# 数字健康周报

## 执行流程

1. 确定出刊日期、报告周期、截止时点、地区、受众和决策重点。用户指定自定义周期或历史补刊时，用户指定的日期口径优先；用户未指定时默认采用当前自然周（周一至周日），出刊日期取该周周日。若生成时报告周期尚未结束（结束日整天均视为未完结，跨入次日零点及之后才算完结），只检索到当前时点，并在标题下明确截止时间和“本周尚未结束”；用户明确要求历史补刊、“上一完整周”或“最近一个完整自然周”时，采用对应的已完结周期，无需标注未结束。
2. 若任务延续既有周报归档，先只读检查最近三期文件名和标题。既有、稳定且与用户要求不冲突的出刊惯例优先于通用默认值；无法确认时明确说明采用的日期口径。
3. 选择与任务有关的检索面：战略研究、监管政策、技术落地、投融资与市场、跨行业参考。
4. 检索当前资料。优先监管机构、政府部门、论文和会议原文、公司公告、研究机构原文及可验证数据集。
5. 同时记录发布时间与事件日期，避免把旧报告的二次传播列为本周新信号。事件日期必须位于报告起始日与截止时点之间；仅作背景引用的旧事件需明确标为背景，不得列作本周事件。
6. 合并转载、摘要和同一报告的不同入口。对高影响结论尽量用独立来源复核。
7. 分开书写：
   - 已核实事实；
   - 来源机构的主张；
   - 基于证据的分析判断；
   - 尚待验证的假设。
8. 不强求每周都出现反共识信号。只有证据与主流判断形成真实冲突时，才列出分歧。
9. 当存在三个以上独立检索面且环境支持并行工作时，可并行检索；否则直接完成。
10. 生成报告并附来源。正式周报完成验证后默认自动归档，无需再次询问或等待用户确认。用户明确要求预览、草稿或不保存时，只在答复中交付并保持只读，不写入归档目录。

## 自动保存与命名

- 保存目录优先级为：用户本次指定目录 > 已确认的既有稳定归档目录 > 当前用户既有 MEMORY 工作区下的 `raw/DigitalHealthWeeklyBrief`。解析不到唯一 MEMORY 工作区时停止写入并报告路径歧义，不另建平行目录。默认行为不授权发布、更新知识库或写入其他系统。
- 默认文件名为 `DHWB-YYYYMMDD.md`，其中日期是出刊日期（自然周默认取该周周日，自定义周期取周期结束日），也是报告周期结束日，不是任意生成日或上一周结束日。
- 先在当前会话隔离临时目录生成与最终文件同名的 UTF-8 定稿，必须通过下述校验器和共享安全归档门禁再发布。不得直接用 `os.rename`、`os.replace`、`shutil` 或普通复制归档；私有草稿保留，其私有权限不得成为正式文件权限。
- 保存前检查目标是否已存在。同一技能、周期和档期才可在全部验证通过后替换；不同语义、快照漂移或旧版身份不明时 BLOCKED，不静默覆盖或擅自改名。新版模板是未来报告的 schema 迁移，受保护的 DHWB 日期/命名规则不变；既有同周期目标缺少新元数据或规范标题时，须人工身份规范化/复核，不能自动重写旧报告。
- 文件名、标题周期、出刊日期和截止说明属于同一语义单元。用户修正其中任一项时，重新检查其余字段，禁止只做局部改名。
- 共享门禁发布后回读 UTF-8 内容、核对 SHA-256 和覆盖的 Windows 安全描述符/访问证据；来源真实性另行人工复核。最终答复报告绝对路径、状态、哈希和访问证据限制；BLOCKED 时保留草稿与恢复证据，不宣称归档成功。

## 输出要求

完整周报按需读取 [references/template.md](references/template.md)。模板与确定性校验器共用规范化标题、日期字段和事件表；没有符合纳入标准的事件时使用模板给出的明确空结果标记，不为通过门禁而凑数。简短请求不必机械填满模板，可使用以下结构：

1. 本周结论
2. 关键事件与来源
3. 政策和市场影响
4. 技术落地信号与证据限制
5. 对医疗信息化业务的传导影响
6. 建议动作与验证节点
7. 信息缺口

每条关键事件至少包含事件日期、主体、动作、影响判断和直接来源。对论文、政策和研究报告优先链接原文，不链接搜索结果页。

`assets/` 下的任务文件只能用于扩展检索面，其中的时间变量服从本次报告周期；[examples/DHWB-Reference.md](examples/DHWB-Reference.md) 是明确标注的合成格式示例，不能作为事实来源。

## 验证门禁

保存前必须满足以下断言：

- 默认报告起始日为周一，结束日为同一自然周的周日，出刊日期等于结束日；显式支持用户指定的自定义周期，起始日不晚于结束日，出刊日期等于结束日。
- 文件名中的日期等于出刊日期；标题同时包含正确的起止日期。
- 首个二级标题前必须各出现一次未加粗的精确字段：`报告周期：YYYY-MM-DD 至 YYYY-MM-DD`、`出刊日期：YYYY-MM-DD`、`生成时点：带偏移ISO-8601`、`报告时区：Asia/Shanghai`。标题必须匹配模板所述规范标题。
- 截止时点（cutoff）必须显式包含时区偏移（ISO-8601，如 `+08:00` 或 `Z`），以真实时刻比较且不得晚于当前系统时间；正文生成时点必须与参数代表同一时刻。报告时区默认 Asia/Shanghai，日历日期、周期完结及跨日判断统一换算至报告时区，cutoff 日期不得早于报告起始日。
- 生成时若报告周期尚未结束（结束日整天均视为未完结，直到跨入次日零点及之后才完结；或结束日仍在未来），正文显式标注截止时点和周期未完结状态；历史补刊或已完结周期的完整报告无需标注周期未完结。
- 所有实际带日期的本期事件行只放在唯一的 `## 关键事件与来源` 中；格式错误的行拒绝。没有符合标准的事件时，在该节独立一行且仅一次写 `本周期未发现符合纳入标准的事件`，删除示例事件行；表头可保留，不得与事件行并存、重复标记或缺少该节。其他章节中的旧事件明确标为背景，不参与本期事件校验，也不能替代本期结果。
- 本周事件日期不早于起始日、不晚于周期结束日且不晚于截止日；历史补刊允许 cutoff 晚于周期结束日，但事件仍不得晚于结束日。校验器只校验日期，不能证明同日事件发生在 cutoff 时刻之前；必须人工核对原始来源时间及可访问性，不能把结构通过当作事实核验。
- 改名、改周期或刷新内容后，重新执行全部断言。

必须使用已解析的绝对路径对隔离临时目录中的同名定稿运行校验器。`skill_dir` 是本技能绝对目录，自有 `scripts/validate_weekly_brief.py` 和 `scripts/test_validate_weekly_brief.py` 从 `skill_dir` 解析；以下四项均为 **skills-root 相对路径**，从 `skill_dir.parent` 解析，不从当前工作目录或本技能目录解析：

- `shared/scripts/report_archive.py`
- `shared/scripts/report_archive_windows.py`
- `shared/scripts/test_report_archive.py`
- `shared/references/report_archive.md`

```powershell
python -B "$validator" --file "$draft" --period-start YYYY-MM-DD --period-end YYYY-MM-DD --issue-date YYYY-MM-DD --cutoff "带偏移ISO-8601时间" --report-timezone Asia/Shanghai
```

`--report-timezone` 可省略，默认 `Asia/Shanghai`；若显式指定其他有效 IANA 时区，正文 `报告时区` 必须使用完全相同的名称。生成时点允许用 `Z` 或其他偏移表示同一 cutoff 时刻，并非必须采用报告时区的偏移。生产 CLI 不提供 `--now`，历史补刊也不得伪造当前系统时钟。

如用户明确指定自定义周期，附加 `--allow-custom-period`；如用户明确指定非标准文件名，附加 `--allow-custom-filename`。随后必须按共享文档执行归档 `validate`（stdout JSON 计划）→ `commit --plan 文件 --allow-target 精确目标`。同样的用户授权自定义选项须传给归档 validate。

Python、时区数据、校验器、共享脚本或已安装 Windows pywin32 能力缺失均 BLOCKED；不能用人工检查替代安全发布门禁，不自动安装、不回退为不安全保存。Windows 以外 fail closed；权限失败不授权扩大权限。自动归档权限、公共来源边界不变；Windows 权限覆盖、并发限制与恢复流程见共享文档。

## 完成检查

- 报告周期与事件日期一致。
- 文件名、出刊日期、标题周期和截止时点一致。
- 关键结论均有可访问来源。
- 事实、来源观点和分析推断已分层。
- 没有把数据缺口隐藏成确定性断言。
- 建议动作包含适用条件或验证节点。
