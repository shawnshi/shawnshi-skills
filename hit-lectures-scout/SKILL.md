# 医疗数字化文献侦察

## 研究边界

- 优先使用论文原文、期刊页面、会议官网、注册平台和作者公开材料。
- 明确区分同行评审论文、会议论文、预印本、技术报告和新闻稿。
- 按研究设计评价证据，不强求每篇论文都有 N 值、P 值或真实世界研究数据。
- 不因缺少商业映射而删除方法学或基础研究；应说明它与当前任务的相关性。
- 样本量、P 值、置信区间、效应量、真实世界证据和临床终点只在研究设计适用且原文报告时填写；否则标明“不适用”或“原文未报告”，不得据此淘汰研究。
- 不把统计显著性等同于临床重要性，不把回顾性关联写成因果关系。
- 除非用户明确要求并提供业务背景，不映射到特定公司、产品或销售立场；涉及厂商时采用可核验的中性比较，不生成攻击话术。
- 必须显式核查被分析版本的撤稿、撤回、更正及关注声明（expression of concern）；核查不可达时如实记录“未知”并相应保守限制结论，禁止默认未撤稿。已撤稿研究不得保留积极有效性结论，但可作为学术诚信或背景事件记录。
- 记录分析版本选择理由与版本关系（预印本/会议/期刊），同一研究只计一次，不重复计数。
- 明确候选采集脚本（如 arXiv 工具）仅为特定领域预印本侦察工具，不代表完整医学与临床文献扫描；必须按任务需求结合 PubMed、期刊官网等互补来源，记录主题与来源覆盖面。
- 输出用于研究与产品决策，不替代临床诊断或治疗建议。

## 执行流程

1. 定义问题、日期范围、疾病或场景、技术类别和纳入排除标准。
2. 搜索多个互补来源，记录标题、作者、发布日期、版本、DOI或永久链接以及同行评审状态。
3. 去重同一研究的预印本、会议版和期刊版，优先分析最新且证据更完整的版本。
4. 提取研究问题、设计、样本、数据集、对照、主要终点、结果、置信区间或统计量以及作者声明的局限。
5. 按研究设计使用合适的评价维度：
   - 临床试验：随机化、对照、终点、样本量和外部有效性。
   - 观察性研究：偏倚、混杂、数据完整性和因果边界。
   - 模型研究：数据泄漏、外部验证、基线、校准、亚组与部署漂移。
   - 方法或系统论文：复现性、数据与代码可得性、计算成本和适用条件。
6. 将学术结论与业务建议分开。每项研发或产品建议都写明它仍需验证的假设。
7. 范围较大且可拆分为不同来源或主题时，可在当前环境支持下并行检索；小型扫描直接完成。
8. 生成正式报告后默认直接归档，无需再次询问或等待用户确认。用户明确要求预览、草稿或不保存时，只在答复中交付并保持只读，不写入归档目录。

## 自动保存与命名

- 保存目录优先级为：用户本次指定目录 > 已确认的既有稳定归档目录 > 当前用户既有 MEMORY 工作区下的 `raw/DigitalHealthLecturesScout`。解析不到唯一 MEMORY 工作区时停止写入并报告路径歧义，不另建平行目录。默认行为不授权发布、更新知识库或写入其他系统。
- 默认文件名为 `DHLS-YYYYMMDD.md`。指定检索窗口时，日期取窗口结束日；未指定窗口时，日期取报告生成日。
- 先在当前会话隔离临时目录生成与最终文件同名的 UTF-8 定稿。确认标题和检索范围一致、正文非空、没有未解析占位符、论文身份及评审状态清楚、永久链接或原始来源齐备后，必须运行下述校验器和共享安全归档门禁；不得直接用 `os.rename`、`os.replace`、`shutil` 或普通复制绕过门禁。私有草稿保留，不把草稿的私有权限带入正式文件。
- 保存前检查目标是否已存在。同一技能、检索窗口、档期和命名依据才可在全部验证通过后替换；不同语义占用、快照漂移或旧版元数据无法证明身份时 BLOCKED，不静默覆盖或擅自改名。新版模板是未来报告的 schema 迁移，不改变受保护的 DHLS 命名规则，也不授权自动重写旧报告；既有同窗口报告缺少新身份字段或规范标题时须人工身份规范化/复核后重新验证。
- 归档身份注意：当前共享归档身份未绑定专题范围与报告时区，同日不同专题或时区的报告可能产生单档命名与身份碰撞。在未来多专题多刊归档合同批准前，同一日期仅支持单一标准 DHLS 档期；如需多专题并行，应显式指定自定义目录或文件名，不擅自修改既有受保护归档身份规则。
- 共享门禁发布后回读 UTF-8 内容、核对 SHA-256 和所覆盖的 Windows 安全描述符/访问证据；另行人工复核论文链接与评审状态。最终答复报告绝对路径、状态、哈希和访问证据限制；BLOCKED 时保留草稿及恢复证据，不宣称归档成功。

## 结构与安全门禁

- 表头之前各写一次未格式化字段：`报告周期：YYYY-MM-DD 至 YYYY-MM-DD`、`出刊日期：YYYY-MM-DD`、`生成时点：带偏移的ISO-8601`、`报告时区：Asia/Shanghai`、`命名依据：explicit` 或 `generated`。这里“表头之前”指首个二级标题之前；标题严格为 `# 医疗数字化文献侦察报告 - YYYY-MM-DD`，日期等于出刊日期。
- 默认报告时区 Asia/Shanghai；按该时区解释日历日期。cutoff 以真实时刻比较，不得为未来或无时区；指定窗口用 explicit 且出刊日为窗口结束日，未指定窗口用 generated 且出刊日为 cutoff 在报告时区的日期。
- 必须有唯一的 `## 本期研究` 和 `## 来源`，可选一个 `## 背景研究`。研究表固定七列：研究ID、日期、标题、评审状态、版本、永久链接、来源编号；来源表为来源编号、原始链接。本期研究日期限窗口和截止日内；背景不计入本期，仍不得晚于截止日。
- 结构门使用无依赖的轻量 Markdown 子集：顶层 ATX 标题（最多三空格缩进），元数据仍须独立未缩进行且在正文标题之前；代码围栏（反引号或波浪号）、缩进代码及 HTML 注释不提供元数据、节、表或编号。研究/来源每节至多一张连续表，首行须为上述唯一正确表头，紧接同列数分隔行（每格至少三个 `-`，可带对齐冒号）；各行保留首尾 `|`，单元格内管道写 `\|`，不得用空行拆开表或以子标题后的行补表。
- 零结果兼容：唯一独立无结果标记且无本期研究行时可不写本期表；全报告无结构化研究、来源条目及来源引用时可不写来源表。也可保留正确表头与分隔行的空表；只要出现表或数据行就必须满足完整表结构。背景仅说明文字可无表，结构化背景行须有自己的七列表头与分隔行。
- R 加数字为全报告唯一研究ID，S 加数字为唯一来源ID；多来源引用用 `S1,S2`，正文 `[R1]`、`[S1]` 必须存在。评审状态限同行评审、会议评审、预印本、未同行评审、评审状态未知；版本必须真实明确，不得编造版本、DOI或来源。无法确认身份/版本时可留在说明或背景文字，或保持研究行 BLOCKED；结构化背景行仍须满足身份字段。无结果用独立一行 `本周期未发现符合纳入标准的研究`，不得与本期行并存。
- 细节另列标题，保留按设计适用的 N/P/区间/临床证据；结构校验不证明 DOI 真实、临床质量或链接可访问。已知模板占位符须清除，普通 Markdown 和真实置信区间（例如 95% CI [0.82, 1.07]）不是占位符。人工原始来源核验不可由结构通过替代；日期粒度同样不能证明同日研究早于 cutoff 的时刻。

路径解析：`skill_dir` 是本技能绝对目录，自有 `scripts/validate_lectures_scout.py` 和 `scripts/test_validate_lectures_scout.py` 从 `skill_dir` 解析；以下四项均为 **skills-root 相对路径**，从 `skill_dir.parent` 解析，而非当前工作目录或本技能目录：

- `shared/scripts/report_archive.py`
- `shared/scripts/report_archive_windows.py`
- `shared/scripts/test_report_archive.py`
- `shared/references/report_archive.md`

先使用已解析的绝对脚本路径运行（示意变量均须替换）：

```powershell
python -B "$validator" --file "$draft" --period-start YYYY-MM-DD --period-end YYYY-MM-DD --issue-date YYYY-MM-DD --cutoff "带偏移ISO-8601" --window-mode explicit --report-timezone Asia/Shanghai
```

未指定窗口改用 `--window-mode generated`；用户明确指定非标准文件名才加 `--allow-custom-filename`。校验通过后必须按共享文档执行 `validate`（stdout JSON 计划）→ `commit --plan 文件 --allow-target 精确目标`。自动归档授权不免除安全门禁：Python、时区数据、校验器、共享脚本或已安装 Windows pywin32 能力缺失均 BLOCKED，不自动安装，不降级为人工批准后的不安全发布。Windows 以外 fail closed；权限失败不授权扩大权限。Windows 权限覆盖、并发限制与恢复程序以共享文档为准。

## 可选资源

- 完整报告可参考 [assets/report_template.md](assets/report_template.md)。
- `assets/task_journals_cn.md`、`assets/task_journals_en.md` 和预印本任务文件可用于制定检索式与记录字段，不得作为论文证据，也不得把其中的建议字段当作纳入门槛。
- 只有在脚本与当前环境兼容且确有需要时，才检查并运行 `assets/deepxiv_preprints_scout.py`；不得自动安装依赖。候选 CLI 最短用法与边界见 [assets/task_preprints.md](assets/task_preprints.md)：默认上海时区含当天共 7 日，可指定历史闭区间/主题，`--max-enrich 0` 保留候选但省去 brief。候选仅写已存在任务隔离目录中的新文件，不是正式 DHLS 报告；partial 不等于空结果，候选写入成功须有终端 verified/hash。预览、草稿或不保存请求仍只读，不运行文件输出。
- 政策/标准只用于独立背景或环境说明，引用来源仍编号；不进入七列研究表，不计研究数量，不以“未同行评审”代替政策分类。

## 输出结构

1. 一句话结论与检索范围
2. 研究矩阵：研究类型、样本、核心结果、证据强度、局限、链接
3. 值得跟踪的技术或临床信号
4. 对研发、产品或市场的可验证假设
5. 争议、复现风险和信息缺口
6. 检索方法与来源

若符合标准的研究少于用户期望数量，报告实际数量并解释原因，不用低质量材料补齐。

## 完成检查

- DOI、论文链接和版本状态已核实。
- 撤稿、更正、关注声明状态已显式核验并记录（含核查日期与来源），不存在以撤稿研究支撑未受限结论的情况。
- 跨版本去重与分析版本理由清楚，同研究未被双计。
- 预印本和同行评审结果已清楚区分。
- 结论强度没有超过研究设计能够支持的范围。
- 统计结果、临床意义和业务推断没有混为一谈。
- 没有为了凑数量、补齐 N/P/RWE 字段或形成商业映射而排除相关研究或引入低质量材料。
- 正式报告已按约定路径归档，并通过发布后回读检查；只读退出请求除外。
