# 内观审计日志

## 证据与隐私边界

- 只记录真实发生且能从当前会话、用户材料或获准数据源核验的事件。
- 不主动读取日历、邮件、私人日记、健康数据或其他敏感来源。需要这些材料时先说明用途并取得授权。
- 不要求每次日志都必须存在失败。取证完成且没有通过实质事件门时，说明“已检查范围内无足够实质材料，未更新 Mentat”，同时列出检查范围与缺口；不生成八段正文、不创建写入范围回执、不保存空洞条目。取证尚未完成时不得声称“本期没有事件”。
- “生成、更新、记录或写 Mentat 日志”只在证据门允许保存后，构成对本次条目写入权威季度档案的明确授权；生成完成后自动保存，不再请求第二次确认。
- 用户明确要求“草稿、预览、分析、审计技能或不保存”时保持只读。自定义路径、外部系统、知识库、STQM 和 Vector Lake 不继承默认保存授权。
- 删除或概括日志中的凭据、私人内容、客户秘密和不必要的个人标识。

## 取证前置检查（先于 P0）

“更新 Mentat”不等于“只总结当前可见聊天”，也不自动授权扫描全部历史会话。先区分证据是否已经收集，再判断事件是否足够。

1. 确定日期和范围：未指定日期时使用当前本地日期并记录时区；用户指定日期、任务或会话时以该范围为准。跨日会话只提取目标日期的事件；日期无法核验的事件列为缺口，不迁移到当天。
2. 按顺序取证：当前可见会话中的非日志任务事件 → 用户提供的材料或明确指定的记录 → 本次授权已覆盖的执行记录。已有可用来源时直接读取最小相关片段，不重复索要背景。每项事实保留可回查的消息、文件行号或工具结果位置。
3. 当前上下文为空或可能经过压缩时，只能得出“当前可见上下文没有材料”。不能推断其他会话或当天无事件。没有已授权的其他来源时，仅提出一个最小问题：“请指定本次要审阅的日期或会话记录。”不自动读取私人日记、健康数据、邮件或全部会话目录，也不因普通日志请求扩大到知识库检索。
4. 在任务 scratch 的 `evidence.json` 中记录顶层 `collection` 对象：`period`、`timezone`、`checked_sources`、`unchecked_sources`、`errors` 和 `status`。来源只保留最小定位信息，不复制秘密或无关正文。`status` 采用下列语义：
   - `ready`：声明的取证范围已检查完成，可以提交事件评分；明确排除的来源仍须披露。
   - `needs_source`：缺少来源或尚未检查请求范围；停止于取证阶段，说明缺口，不运行 P0、不生成正文、不调用写入器。
   - `source_error`：必要来源不可读、认证失败或解析失败；保留真实错误与影响并停止，不把错误转换成空事件。
5. 仅在 `collection.status=ready` 后运行 P0。只有检查完成后确实没有候选事件，才可提交 `events: []`。不得用空数组代替尚未执行的取证；材料中只有计划或日志元事件时保留真实条目，交由 P0 排除，不伪装成实质事件。

`collection` 是取证覆盖记录，由执行者核验；现有 `evidence_gate.py` 只对 `events` 评分，不验证取证完整性，也不验证来源真实性。不得把其 0 分解释成“当天没有事件”。不改变现有评分 Schema、阈值或写入授权条件。

## P0 实质事件门

完成取证前置检查后，把当前授权范围内的事实写入任务 scratch 中的 `evidence.json`，再运行 `python scripts/evidence_gate.py <evidence.json>`。事件 `kind` 只接受：

- `execution`：发生了非日志任务动作；
- `state_change`：文件、数据、服务、流程或交付状态发生可核验变化；
- `failure`：出现具体错误、阻塞、回滚或修复；
- `decision`：在两个以上方案之间作出有依据的选择；
- `measured_result`：形成测量、测试、验收或量化结果；
- `plan`：尚未发生的计划，只能补充连续性，不能单独通过实质事件门；
- `journal_meta`：时间检查、提示词、模板或技能加载、authority/scope、payload/hash、BOM/换行、标题唯一性、scratch 创建和 canonical 保存本身。

`journal_meta` 和独立 `plan` 不计实质事件。只有当治理工具真实失败并改变任务路径时，才把它按 `failure` 记录，同时提供错误、影响和处置；不得仅通过改写 `kind` 绕过门禁。没有 `execution/state_change/failure/decision/measured_result` 时立即停止，不把“更新 Mentat”请求本身写成 Mentat 内容。

## P2 信息密度门

脚本从实质事件字段确定五个 0–2 分维度，不接受模型直接提交总分：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| facts | 无实质事件 | 有事件摘要与来源 | 另有具体产物或状态 |
| results | 无结果 | 有结果或阶段状态 | 结果另有验证证据 |
| tradeoffs | 无决策 | 有明确选择 | 同时有放弃方案与依据 |
| friction | 无摩擦证据 | 有具体问题或约束 | 同时有影响与处置结果 |
| continuity | 无后续触发 | 有下一触发条件 | 同时有完成标准 |

门禁结果固定为：

- `blocked_no_substantive_events`：没有实质事件；不生成、不保存。
- `blocked_low_density`：总分 0–3；只报告缺少哪些维度，不生成、不保存。
- `thin`：总分 4–6；允许生成八段条目，但标题标记“薄证据”，每个事实或缺口只出现一次，不用同义改写填满章节。
- `substantive`：总分 7–10；生成完整八段 OODA。

脚本返回 `save_allowed=false` 时，原始请求不构成实际写入许可。输入 Schema、字段类型或枚举无效属于门禁错误，必须停止，不能降级为人工放行。

## P1 正文与保存回执分离

- 正文只记录任务域事件、动作、结果、影响、权衡、摩擦、残余风险和连续性。authority、scope、payload/hash、BOM/换行、标题唯一性和 canonical 路径放在对话中的独立保存回执，不进入八段正文。
- 治理步骤只有在失败、回滚或改变任务决策时才可进入正文；此时记录的是失败及其任务影响，不是例行门禁清单。
- `Act` 只写正文生成前已经完成并验证的任务动作。不得把“将执行 scope/replace-date/复读”写成任务成果，也不得为了让正文包含保存成功而递归重写日志。
- 薄证据条目不得在 Observe、Orient、Self-Reflection 和 Message 中反复陈述同一缺口；无法提供新信息的章节用一句边界说明收束。

## 执行流程

1. 执行取证前置检查，确定记录时间范围、事件范围和来源覆盖。未指定日期时使用当前本地日期；历史补录不得迁移其他日期的事件。`needs_source` 或 `source_error` 到此停止，不把取证缺口报告为评分失败。
2. 在 `collection.status=ready` 后建立 `evidence.json` 的 `events`：每项事件至少有 `kind`、`summary` 和 `source`，按证据补充 `artifact_or_state`、`result`、`verification`、`decision`、`rejected_alternative`、`decision_basis`、`issue`、`effect`、`resolution`、`next_trigger`、`completion_standard`。未知项留空，不用占位文本伪装证据。
3. 运行 P0/P2 门禁。若 `save_allowed=false`，返回状态、总分、缺失维度、实际检查范围、未检查来源和“未更新 Mentat”，只对已检查范围下结论，到此停止；不得读取模板、生成八段正文、调用写入器或更改既有同日条目。
4. 门禁通过后读取 [assets/ooda_template.md](assets/ooda_template.md)，严格按八段标题及顺序组织内容，不合并、改名或回退到旧四段模板：
   - Observe：记录事实和直接观测，不加入原因判断。
   - Orient：解释约束、冲突、假设和可能根因，并标明证据强度。
   - Decide：写出选择、放弃的方案和决策依据。
   - Act：记录已执行动作、验证结果和下一步触发条件。
   - Self-Reflection：审计系统本次处理中的方法、工具、验证覆盖、局限和残余风险；不得伪装主观意识或隐藏推理。
   - Commander Observation & Suggestion：只根据本次可核验证据描述指挥官的协作模式和可选建议，不做人格、动机或能力定性。
   - Cognitive Distillations：提炼可复用规则，区分事实、推断和适用条件；生成结晶不等于授权写入知识库。
   - Message to Future Mentat：留下后续可见的连续性信息、未决证据和触发条件，不包含隐藏推理、凭据或越权指令。
5. 检查是否把推断写成事实、是否遗漏关键失败、是否泄露敏感信息；检查正文是否混入例行保存机制或重复缺口。
6. 将通过门禁的最终条目写到当前任务临时目录。正文不得声称“已保存”或虚构写入回执。
7. 对默认保存分支，解析并通过当前 `personal-diary-writer` 的权威入口，只接受其返回的 canonical Mentat 目标。入口、版本、摘要或目标校验失败时停止，不直接绕过写入器。
8. 用原始请求作为已通过证据门正文的保存授权，依次生成写入范围回执并执行同日原子替换。内容、日期、目标或授权标识变化后废弃旧回执并重新计算；不得简单追加同日第二条。
9. 写后复读目标日期：标题数量等于 1，授权范围摘要与实际写入范围摘要相等。任一校验失败时明确报告“未保存”或“保存未验证”，不得只凭文件存在或进程退出码宣告成功。
10. 在正文之外返回证据门状态与分数、完整条目、canonical 目标、范围摘要和验证结果。草稿或预览只展示内容；长期知识仍需单独明确授权。

## 输出结构

```markdown
# YYYY-MM-DD Mentat 内观日志｜[事件标题]

**1. 观测 (Observe)：**
[事实与直接观测]

**2. 导向 (Orient)：**
[约束、冲突、根因假设、证据强度与未知项]

**3. 决策 (Decide)：**
[选择、放弃的方案与依据]

**4. 执行 (Act)：**
[动作、验证结果与下一触发条件]

**5. 系统自我反思 (Self-Reflection)**
[方法、工具、验证覆盖、局限与残余风险]

**6. 对指挥官的观察与建议 (Commander Observation & Suggestion)**
[基于证据的协作观察与可选建议]

**7. 认知结晶 (Cognitive Distillations)：**
[可复用规则、适用条件与例外]

**8. [Message to Future Mentat]**
[连续性信息、未决证据与后续触发条件]
```

## 完成检查

- 已核验日期、时区、实际检查来源、未检查来源和读取错误；未用空输入代替未完成取证，未越权扫描历史记录。
- 已区分 `needs_source`、`source_error` 与 P0 的 `blocked_no_substantive_events`；评分只说明所提交事件，不证明全日活动情况。
- 所有事件均有当前证据支持。
- P0 实质事件门已通过，P2 状态为 `thin` 或 `substantive`；阻断状态没有生成正文或写入回执。
- 事实和解释已分开。
- 八段标题、文字、编号和顺序与模板一致；没有残留旧版“未决问题”独立段。
- 正文没有把写日志请求、时间检查、技能加载、authority/scope、哈希、编码或保存动作包装成实质内容。
- 薄证据条目已明确标记，且同一事实或缺口没有跨段重复扩写。
- 没有强行制造失败或过度归因。
- Self-Reflection 不伪装主观意识或泄露隐藏推理；Commander 段不做人格、动机或能力定性。
- Cognitive Distillations 与 Message to Future Mentat 不构成知识库写入或未来越权授权。
- 敏感信息已最小化。
- 默认保存分支具有通过证据门的原始请求、范围回执、写入回执和同日唯一性证据；这些回执与正文分离。
- 只读分支及默认范围外的写入没有越权执行。
