# 厂商评价方法

## 一、先定义评价目的

在比较前明确目的：市场格局描述、供应商初筛、采购适配、竞争对标或投资初筛。不得把一种目的的得分直接用于另一种目的。

## 二、设定纳入条件

根据市场特点公开至少三项纳入条件，例如：

- 在目标地域提供符合市场定义的产品或服务；
- 在截止日期前仍保持商业运营；
- 有可核验的客户、收入、部署或合作证据；
- 达到用户指定的规模、合规或交付门槛。

厂商少于五家时按实际数量分析。市场高度碎片化时按玩家类型分组，不声称清单完整。

## 三、默认评价框架

优先使用评分表，而不是强制二维象限。以下权重是起点，必须按决策场景调整并披露调整理由：

| 一级维度 | 默认权重 | 二级指标示例 |
| --- | ---: | --- |
| 产品与场景适配 | 20% | 功能完整性、易用性、集成、性能、可配置性 |
| 客户与结果验证 | 20% | 可核验客户、生产使用、续约、业务或临床结果 |
| 交付与服务能力 | 15% | 实施方法、覆盖区域、伙伴体系、SLA和支持 |
| 商业与运营韧性 | 15% | 收入质量、客户集中度、成本结构、持续投入能力 |
| 技术与数据能力 | 15% | 架构、数据、AI、安全、互操作和可扩展性 |
| 战略差异化 | 10% | 路线图、细分聚焦、生态位置和可防御性 |
| 合规与风险 | 5% | 监管资质、隐私、安全、诉讼或重大依赖 |

供应商选型时增加客户特定的适配度、TCO、迁移成本、合同锁定和验收能力；投资初筛时增加增长质量、资本需求、竞争壁垒和下行风险。

## 四、评分规则

采用1—5分并描述锚点：

| 分值 | 解释 |
| ---: | --- |
| 1 | 无可靠证据，或明显低于基本门槛 |
| 2 | 有局部能力，但证据薄弱或覆盖有限 |
| 3 | 达到目标市场的常规可用水平 |
| 4 | 多项指标有独立证据支持，明显高于常规水平 |
| 5 | 持续、规模化且可复核地领先，证据充分 |

没有证据不得默认给3分。区分两种N/A：

- **证据缺失**：该指标适用但没有足够证据。保留原权重，不按单家厂商重新归一化；同时报告证据覆盖率。证据覆盖率低于70%时不得计算可比较的总排名，只能给出暂定区间和待核验项。
- **业务不适用**：该指标对本次评价对象确实不适用。必须在评分前对所有厂商采用相同处理，并公开删除或重新分配权重的方法。

加权得分按 `Σ(单项得分 ÷ 5 × 指标权重)` 计算；证据覆盖率按 `已有可评分证据的权重之和 ÷ 总权重` 计算。展示原始分、权重、加权结果、证据覆盖率和证据强度，避免只有最终排名。

会改变结论的加权得分、证据覆盖率和敏感性结果，必须使用当前可用的 Python 确定性复算；记录输入、权重单位、公式、舍入规则和执行结果，检查总权重及 N/A 处理符合上述规则。无可用 Python 或执行失败时，标注“未复算”，只交付原始证据、输入和计算方法，不臆算总分、覆盖率或确定性排名；无需新增专用脚本。

## 五、证据处理

- 区分法定披露、官方产品文档、客户公开案例、第三方评价和厂商自述。
- 不把融资金额、媒体曝光或技术演示自动等同于产品成熟度。
- 不把签约、试点或合作备忘录等同于生产部署和业务成效。
- 对客户数量、收入和部署规模核对定义与截止日期。
- 对无法核验的能力写“未找到足够公开证据”，不要写成“没有该能力”。

## 六、二维定位图

只有二维关系确实有助于理解时才使用定位图。自行定义并披露两个轴，例如：

- 横轴：目标市场执行能力；
- 纵轴：战略差异化与未来适应性。

不得使用“魔力象限”、领导者、挑战者、有远见者、利基玩家等第三方专有分类。不要暗示任何第三方机构参与、认可或背书。

二维位置是公开证据下的暂定分析，不是绝对排名。对证据不足的厂商标注低置信度或不定位。

## 七、推荐输出

厂商比较至少包含：

1. 评价目的、范围、纳入条件和截止日期；
2. 指标、权重和评分锚点；
3. 主表不超过八家厂商和六个核心比较字段，更多细节放入附录或分组；
4. 每家厂商的优势、约束、适用场景和证据缺口；
5. 结论置信度及需要厂商澄清的问题；
6. 对采购方或竞争方的下一步验证动作。

避免诋毁性、绝对化或无法核实的描述。负面判断必须与证据强度匹配。
