# SVG 技术图布局规范

本参考用于需要人工坐标、复杂路线或视觉修正的情况。普通图优先使用 [输入契约](input-schema.md) 中的自动布局，并按 [输出 QA](output-qa.md) 验证结果。

## 1. 先确定阅读顺序

- 流程和分层架构默认上到下（`TB`）；调用链、管道和时间关系可左到右（`LR`）。
- 主路径保持单一方向；反馈、异常和异步关系放在外侧通道。
- 同一层节点对齐，尺寸相近；不同层用容器、标题或留白区分。
- 一张图出现两个以上同等重要的阅读起点时，优先拆图或增加明确编号。

## 2. 间距和画布

| 项目 | 建议值 | 说明 |
|---|---:|---|
| 外边距 | 32–48px | 包括标题、图例和页脚 |
| 同层节点间距 | 48–96px | 长标签或多箭头时取较大值 |
| 层间距 | 80–120px | 为箭头和标签预留通道 |
| 箭头离非目标节点 | ≥16px | 密集图无法满足时应扩大画布或拆图 |
| 节点内边距 | 12–20px | 中文与英文均需实测 |

布局完成后以全部可见元素的联合边界确定 viewBox，必须纳入：节点、容器、箭头路线、箭头标签、图例、标题、页脚、外置说明和负坐标。不要只根据节点右下角扩展画布。

## 3. 节点和文字

- 先保证 12px 以上正文可读，再考虑压缩画布。
- 长标签优先换成 2–3 行；仍放不下时增宽或增高节点。
- 同类节点使用一致的主标签、说明和类型标签基线。
- 不把纯颜色当作唯一编码；重要状态同时使用文字、线型或形状。
- 中文字体使用系统可用的 CJK 回退栈。交付前在实际环境确认没有空白字或方框。

## 4. 端口和路线

- 箭头连接节点边界的中部区域，避免直接落在角点或节点内部。
- 多条边共享一侧时错开端口；不要让箭头头部互相覆盖。
- 主路径优先正交线。人工 `route_points` 中相邻点只能共享 x 或 y，除非图型明确需要斜线。
- 线路不得穿过非目标节点、节点标签、图例或容器标题。
- 自动布局移动节点后，不保留旧路线提示，除非已经逐条重新验证并显式设置 `preserve_route_hints: true`。
- 环路和反馈边走图外侧；跨层长边使用独立通道，避免与主路径混成一条线。

## 5. 箭头标签

- 标签使用“动作 + 对象”或接口名，例如“读取患者索引”“POST /orders”。
- 放在最长的水平或垂直线段附近，并与线条保持 6–10px 偏移。
- 标签背景应与画布协调；背景不能遮住其他关系或制造假的断线。
- 多条平行边的标签错开至少一行文字高度。

## 6. SVG 渲染顺序

从后到前建议为：

1. 背景；
2. 容器和分区；
3. 箭头路径；
4. 节点形状；
5. 节点文字；
6. 箭头标签；
7. 图例、标题和页脚。

若标签需要背景块，背景块应与标签文本相邻渲染，并位于箭头之上、节点主内容之下。

## 7. 样式适配

- Style 1：坐标优先贴合 8px 网格，适合作为通用默认。
- Style 2：检查深色背景上的细线和小字对比度。
- Style 3：蓝图网格不能干扰容器虚线、时序生命线或表格边界。
- Style 4：可使用较紧凑间距，但不能低于可读性和碰撞门槛。
- Style 5：减少节点和透明层数量，不用于密集 ER、时序或状态图。
- Style 6：使用暖色令牌但保持语义中立，不把色彩解释为业务状态。
- Style 7：白底细线图要保持充分留白，避免靠降低字号容纳密度。

## 8. 修正顺序

发现视觉问题时按以下顺序处理：

1. 修正错误拓扑和关系方向；
2. 调整画布方向或拆分图；
3. 增加节点、层级和外边距；
4. 重跑自动路由或重设少量路线提示；
5. 调整标签和图例；
6. 最后才微调颜色、圆角或装饰。

不要通过缩小字体、隐藏标签或删除图例来掩盖布局问题。
