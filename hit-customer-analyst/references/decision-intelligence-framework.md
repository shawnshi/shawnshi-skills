## 用途与证据前提

机构研究、人物研究、综合研判和交流策略读取本文件。目标是回答：客户当前要完成什么、哪些正式角色影响决策、项目窗口在哪里、我司是否适合合规承接、主要风险是什么。

所有判断按 [信息源、主张、证据与合规规则](source-profile-rules.md) 同时记录：

- `claim_type`：F/F2/A/H/R；
- `provenance`：public/U/N；
- `verification_status`：`{asserted,verified_single,corroborated,conflicted,stale,invalidated,unusable}`。

U/N只表示来源，不表示已核实。分析必须回指主张ID，并写推理、反证或替代解释、置信度和验证问题。

## 客户类型分支

先锁定`customer_type`，再选择对应研究重点；不得把医院模板机械套到其他主体。

| 类型 | 核心任务 | 业务与评价重点 | 典型决策角色 |
|---|---|---|---|
| 医院 | 医疗质量、学科、运营、患者服务、科研和院内治理 | 绩效考核、等级/专科评价、电子病历、互联互通、智慧服务/管理 | 党委/院领导、业务分管、信息、医务、护理、运营、财务、采购 |
| 卫健行政 | 区域治理、资源配置、医防融合、基层和监管 | 区域规划、监测预警、协同服务、绩效和数据治理 | 主管领导、规划信息、医政、公卫、基层、财务和项目执行单位 |
| 医保/支付方 | 基金安全、支付改革、结算、监管和便民服务 | DRG/DIP、智能审核、基金监管、数据质量和协同 | 主管领导、待遇保障、医药服务、基金监管、信息、财务 |
| 医疗集团/医联体 | 一体化治理、资源协同、标准统一和成员机构运营 | 集团管控、同质化、共享中心、数据平台、集中采购 | 集团领导、成员机构负责人、业务/信息/运营/财务/采购 |

客户类型不明或混合时，分别写明主体层级、研究范围和不合并边界。

## 机构决策画像

九个通用维度按客户类型解释：

| 维度 | 要回答的问题 |
|---|---|
| 战略导向 | 当前规划、年度任务和上级要求是什么 |
| 业务导向 | 对应客户类型的核心业务目标和绩效压力是什么 |
| 技术导向 | 平台、数据、AI、标准、信创和安全路线有哪些直接证据 |
| 采购治理 | 采购组织、预算、审批、总集成/分包和周期特征是什么 |
| 创新采用 | 是否有连续试点、示范、科研转化或规模推广证据 |
| 风险约束 | 政策、财政、数据、伦理、审计、验收和存量系统约束是什么 |
| 决策结构 | 哪些正式角色承担决策、审批、预算、技术、采购和验收职责 |
| 执行能力 | 跨部门治理、项目推进、上线和验收能力有哪些信号 |
| 当前窗口 | 在建、待建、续建、替换、验收或政策窗口是什么 |

每维输出：结论或明确缺口、主张ID、推理、反证/替代解释、置信度、业务意义和验证问题。重大判断不得只依赖单一新闻或厂商案例。

## 人物画像与角色边界

### 身份与履历

1. 完成姓名、当前机构、现职、地域/范围和至少一个唯一识别项的预验证；
2. 记录任职时间、正式分工、专业和履职相关经历；
3. 无法确认的年份和经历标缺口，不补齐、不推断异常调整原因；
4. 现职和分工优先最近6个月官方原始来源。

### 公开观点与持续关注

标准/深度版可回溯近10年讲话、访谈、署名文章、论文、标准和项目发言，近期3年权重更高。区分本人表达、机构立场、会议主题和媒体概括；单次活动只能形成事实，跨时间、跨场景且来源独立的连续证据才能形成持续关注分析。

### 正式项目角色

角色按具体事项和阶段记录，不用笼统的“决策者”覆盖全部流程：

| 角色 | 所需证据 |
|---|---|
| 发起/业务责任 | 正式分工、任务文件或持续负责证据 |
| 预算/审批 | 明确授权、审批职责或法定流程文件 |
| 采购程序 | 采购职责、采购文件或正式工作分工 |
| 技术评审 | 专家组、技术负责人或评审文件 |
| 合同/实施 | 签署授权、项目负责人或实施文件 |
| 验收/运营 | 验收组、运营责任或正式记录 |

主持会议、项目讲话、出席启动会或领导小组成员，只能证明相应范围的项目参与，不能自动证明预算、评标、采购审批或合同决定权。

### 人物决策画像

输出政策、业务、技术、采购治理、创新、风险、管理协同、汇报适配和决策约束九维判断。管理风格、汇报方式和可能关注默认是H；不得写成性格定论。

“采购治理”只分析公开职责、程序关注和决策条件，永不推断个人厂商偏好。

## 采购与项目归因

强制分三层：

1. **机构采购事件**：采购单位、项目/包件、编号、预算/中标/合同金额、供应商或联合体、建设内容、阶段、日期和直接来源；
2. **岗位项目关联**：目标人物在发起、预算、采购、技术、合同、实施、验收中的明确角色及证据；
3. **允许分析**：机构采购模式、技术评价要求、存量依赖、供应商格局和合作惯性。

禁止：

- 将机构采购结果归因为个人偏好；
- 因某人在任期内出现多次同厂商中标而推断其厂商倾向；
- 由会议主持、讲话、合影或一般领导小组成员身份推断采购权；
- 从不完整公开公告推断市场份额、独家关系或未发生采购。

采购时间线覆盖意向、公告、中标、合同、实施、验收、运维，同时允许废标、终止、重招、变更、分包、联合体和阶段未公开。缺失阶段标“本次未核验”，不得补齐。

## 判断链与G-C-P

### 判断链

```text
客户发展/履职阶段 → 核心任务或矛盾 → 正式角色关注 → 数字化支撑点 → 最小推进动作
```

每个环节写：主张ID、推理桥接、反证或替代解释、置信度和现场验证问题。不要强迫所有客户形成单一因果链；至少保留一个替代解释，并允许“暂不形成项目”。

### G-C-P

| 模块 | 要回答的问题 |
|---|---|
| G：Goal | 客户最需要完成的1—2项可验证任务是什么 |
| C：Capability | 我司哪类能力与任务匹配，授权证据、差异化、边界和不匹配项是什么 |
| P：Policy & Project Risk | 合规硬约束、项目交付风险和商业风险分别是什么 |

先确认G，再匹配C；不得从已有产品反推客户需求。C必须允许“待匹配、无匹配或不建议推进”。产品、案例和指标只使用当前授权资料，缺少材料时写“待匹配能力/案例”。

## 机会资格、竞争与投入决策

标准拜访包和战略客户包必须把研究转成可验证的机会判断，不以“客户重要”代替资格。

### BANT与采购时序

| 维度 | 必须回答 | 证据不足时 |
|---|---|---|
| Budget | 预算来源、预算状态、金额口径、审批约束 | 写未知及验证问题，不从项目规模猜金额 |
| Authority | 业务、技术、预算、采购、合同、验收各阶段正式角色 | 按角色层级表达，不笼统写“决策人” |
| Need | 客户要完成的业务任务、评价压力和可观察结果 | 保持H，不把我司产品功能写成客户痛点 |
| Timing | 规划、预算、采购、实施、验收和运营节点 | 分清已发生、计划、推测和未公开 |

另行记录采购方式、资金性质、牵头部门、必要前置条件、存量合同/系统约束和下一可验证节点。BANT不是打分事实概率；任何未知项必须保留。

### 竞争位置

只允许分析：

- 客户已公开或内部授权的存量系统、供应商、合同和项目阶段；
- 客户采购要求、技术路线、交付约束和切换成本；
- 我司与客户目标的匹配、差异、证据和明确短板；
- 竞争情景及现场验证信号。

不得把机构采购归因于个人偏好，不把未命中解释为“没有竞争对手”，不输出绕过采购程序的关系策略。

### win/no-go与投入建议

统一使用：

| 值 | 含义 |
|---|---|
| win | 需求、角色、时序和能力匹配已有较强证据，可主动推进 |
| conditional_win | 存在明确机会，但至少一个关键前提需验证或补齐 |
| monitor | 当前窗口、预算或能力匹配不足，低成本维护并等待触发条件 |
| no_go | 合规、能力、交付、商业或采购条件使继续投入不合理 |

每个判断必须写：依据claim_id、关键缺口、反证、下一验证动作、建议投入强度（低/中/高）和复核日期。战略客户包还需给出“继续投入的停止条件”，例如预算取消、关键能力不匹配、采购窗口关闭或交付风险不可接受。

### 执行闭环

每个有效机会只保留一个主推进动作，并明确：

```text
action｜owner（真人/稳定角色）｜due_date｜依赖｜完成标准｜回填目标
```

没有明确owner或日期的建议不能算可执行下一步。

## 冲突、失效和置信度

上游关键主张包括主体、当前职务、正式分工、项目角色、合作事实、采购阶段、存量系统和承诺。出现以下任一情况时，停止把相关判断升级为正式成果：

- 主张的`verification_status`为`conflicted`、`stale`或`invalidated`；
- 支撑来源权限高于目标成果；
- 身份或项目范围未锁定；
- 新证据实质改变原判断链或G-C-P。

模块返回受影响的主张ID和`downstream_invalidation`。主流程负责把依赖的综合判断、策略和客户信设为`freshness_status: stale`、`review_status: changes_requested`；冲突解除并重新审核前不得外发。

置信度使用主张级高/中/低，并同时展示覆盖缺口。综合100分如保留，只能表示覆盖和证据可靠性；身份未锁定、关键采购事实冲突或受限证据不可复核时，不得给高分。不得使用未经验证的固定权重推导事实概率。

## 合规与自查

- 客户类型分支正确，没有把医院字段套用到卫健、医保或集团；
- U/N没有被当作核实结论；
- 分析有主张ID、推理、反证/替代解释和验证问题；
- 正式角色按项目阶段核验；
- 未推断个人厂商偏好、私人关系或敏感属性；
- G先于C，且保留无匹配/不推进选项；
- 冲突和上游变化已返回下游失效信号；
- 受限信息没有进入更低权限成果；
- 未输出规避采购、监管、审批、审计或数据安全要求的建议。

任何核心项不通过，继续修订，并按影响标`partial`或`blocked`，不能标`completed`。
