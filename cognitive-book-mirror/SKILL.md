# 个人化伴读

## 确认材料与隐私范围

1. 确认书籍、文章或摘录，以及用户希望解决的问题。
2. 默认只使用当前对话和用户主动提供的文本。
3. 只有用户明确同意并指定来源后，才读取日记、记忆、价值观文件或其他私人资料。不要自行扩大日期范围，也不要自动读取治理文件、历史聊天或健康资料。
4. 在输出中标明个人映射所依据的材料；没有证据时写“缺少个人依据”，不要编造经历或动机。

## 提取与映射

1. 提取作者的核心问题、关键主张、论证链、例证和适用边界。
2. 把事实、作者观点和解释者推断分开。
3. 按主题建立双栏：
   - 原著骨架：忠实压缩作者的论点和证据；
   - 个人映射：指出它与用户目标、习惯或既往材料的吻合、冲突和行动含义。
4. 每条个人映射都附依据或不确定性。不要为了保持双栏对称而强行关联。
5. 保留作者最强反例，避免把书的主张当成普遍规律。

## 处理长文本

- 常规长度由主代理直接处理。
- 只有文本可按章节独立拆分且当前环境支持并行时，才使用子代理；统一章节术语、引用位置和个人材料边界。
- 如需结构化提取，只能对用户显式指定的 `.md` 或 `.txt` 运行 `python scripts/extract_and_pack.py --file <path> --output-dir <scratch-dir>`；个人上下文必须逐个使用 `--context <path>` 指定。脚本不得自动查找日记、治理文件、历史聊天或调用其他技能。
- PDF、EPUB 或 Office 文件先使用当前可用的转换能力，在用户指定的临时位置生成文本；本技能不自动转换、不修改源文件。
- 合并分片时使用 `python scripts/stitch_and_format.py --results-dir <dir> --output <file>`；输出路径必须显式提供，不得写入记忆库。
- 两个脚本只使用 Python 标准库，无需安装额外依赖。

## 验证分层

- 硬错误：输入不存在或不是 UTF-8、类型不支持、结果编号未从 1 开始或不连续、必需控制字段缺失、分片没有有效内容。正文中的模板或代码示例不得仅因符号形态被阻断。
- 软提示：章节长短不均、映射数量少、输出未采用双栏表、个人依据较少、措辞风格。
- 人工判断：作者观点是否被准确还原、个人映射是否成立、行动是否值得执行。脚本不得用字数、关键词或固定条目数替代判断。

## 交付

根据长度选择 Markdown 双栏表或分节双栏，避免为追求表格形式损害可读性。
结尾可按任务需要概括值得保留的观点、与既有认知的冲突、可验证行动和
证据不足之处；数量与是否提供行动应由材料和用户目标决定，不设固定条目数。

默认只在当前对话交付。保存文件、更新记忆或写入知识库必须由用户单独明确授权，并使用用户指定的位置。语气可以直接，但不得羞辱用户、推断私人动机或把解释包装成事实。
