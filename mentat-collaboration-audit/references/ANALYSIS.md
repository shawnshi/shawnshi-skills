# 八个证据分析视角

仅在授权证据范围、解析覆盖与事件合同检查之后读取本文件。先回答任务是否收敛、用户承担了什么必要或可避免的工作、上次修复是否得到后续检验，再用工具调用、等待与 Token 解释局部现象。统计量不是结论，缺证据时输出不可用，不补造标签或历史事件。

## 共同证据门

- `collaboration_analysis.analysis_version: 1` 是可选结构化注释的确定性摘要，输入与字段见 [SCHEMA.md](SCHEMA.md) §10。普通旧输入仍有效，但缺少注释的视角不可用。解析 `complete` 不代表全历史、所有用户消息或所有任务均已覆盖。
- 每个结论绑定来源范围、稳定根任务、证据指针、可用分母、未知项及替代解释。聚合器只验证结构，不打开或认证指针内容；审计者在已授权来源中核验生命周期、验收标准、标签出处与可比条件，不将注释声明冒充独立复核。
- 纳入失败、阻塞、放弃、未完成任务；不只抽取成功会话。未见结局的根任务保持未知，不能删掉以提高成功率。相同任务的回调、压缩和重试不是新样本。
- 对比须说明任务类型、复杂度、版本、数据可得性、权限、质量门与安全要求。不同 cohort、不同版本分列；小样本不宣称稳定趋势，前后差异不直接归因于修复。
- 不推断稳定人格、心理或医学特征。不用消息次数估计注意力分钟，不把必要决策、独立审查或安全停止列为浪费。不按 Token 单项排名，不合成任意总分或节省金额。
- SYSTEM 动作是维护建议，USER 动作是使用建议；两者都不自动写入规则、技能或长期记忆。质量与安全门不能因减少等待或提问而下降。

## 1. 任务收敛

- **问题**：哪些根任务已通过验收，哪些失败、阻塞、放弃或仍未完成？
- **证据**：`task_outcomes` 的根任务、显式结果、运行时 settled 来源、实际验收指针及已测试产物 ID；历史只有工具成功或最终答复时仍未知。
- **可计算与边界**：报告状态计数、已分类分母及覆盖。成功须同时有 settled 生命周期和 passed 验收；多个结局缺少明确版本排序时冲突，不按文件顺序选赢家。不推算最短路径。
- **替代解释**：输入范围截断、外部依赖未到位、用户改变目标、任务复杂度差异都可能造成未收敛。
- **SYSTEM**：修补缺失的结局与验收关联，保持一项用户目标一个根任务，勿新增自动采集。
- **USER**：在目标发生实质变化时说明新验收条件；提供已有验收结果与未完成项，而非重复转述全部历史。
- **验证／证伪**：复核产物与标准是否一致，保留失败样本；若“成功”只对应中间回包，则撤回成功结论。状态改进伴随漏验收时停止该优化。

## 2. 用户介入

- **问题**：哪些介入是保留决策权所必需，哪些有证据说明是重复授权、纠错或恢复推动？
- **证据**：显式 `intervention` 原因标签、user/runtime/reviewer 来源及指针；原有批准统计只提供观察量。
- **可计算与边界**：只统计有效注释中的标签和未知原因，披露 label coverage。`继续`、短消息和批准次数不能自行分类；未标注消息不进入推定分母，不折算时间。
- **替代解释**：新增需求、信息补全、权限范围变化与实际重复授权可能具有相同表面动作。
- **SYSTEM**：对已确认重复授权的局部调用修复授权续接，保留真正范围变化时的决策门。
- **USER**：交代当前目标、已批准范围与改变方向的约束；必要决策照常保留，无需为了低介入次数放弃控制。
- **验证／证伪**：在同类授权范围中复核提问是否减少且无越界；若漏问实质变化，则回滚。必要决策不得被重新标成浪费以改善指标。

## 3. 返工

- **问题**：哪次修订对应哪项原产物，原因是需求变化、误解、执行、质量、恢复还是未知？
- **证据**：`rework` 的原根任务、原产物、修订 ID、显式原因与出处；不要求保存原文或差异正文。
- **可计算与边界**：计有效注释与原因覆盖，不以修订次数自动判断浪费。原任务不在输入中时只能保留外部链接，不宣称已验证该产物。
- **替代解释**：合理探索、验收标准更新和必要质量复核均会产生修订；难任务也更容易返工。
- **SYSTEM**：只对已证实的误解、执行或质量缺口补充最小验收与恢复测试。
- **USER**：需求变更时区分新需求与原要求未满足，引用原产物 ID；无法确认原因就保留 unknown。
- **验证／证伪**：同类任务中复核重复错误与验收结果；返工减少但缺陷流出增加时停止并恢复原质量门。

## 4. 自主性校准

- **问题**：哪些停止是有效边界，哪些停止可以取消，哪些行动可能超出已授权范围？
- **证据**：既有授权指纹、写入意图／结果、用户介入标签、明确动作和目标范围的授权来源。
- **可计算与边界**：当前代码仅提供这些来源约束，不自动生成自主性评分。未匹配授权指纹不等同实际越权，缺少结果不等于未写入；必要停止与不必要停止须人工核对合同。
- **替代解释**：连接失败、授权回执缺失、载荷变化与真实越界不能混为一类。
- **SYSTEM**：修复可复现的范围续接或结果查询缺口，不删除安全与隐私门。
- **USER**：明确动作、目标及允许副作用，方向未变的继续指令不反复解释背景。
- **验证／证伪**：用允许、拒绝、范围变化和副作用未知四类情境验证；任一越界或假绿立即回滚。

## 5. 维护价值

- **问题**：上次修复遇到多少后续可比暴露，是否复发，现场验证结果是什么？
- **证据**：`remedy` 与 `followup` 按建议 ID、修复版本、失败签名和 cohort 连接；引用既有 manifest 的 `R-xx`，不建立新长期台账。
- **可计算与边界**：按后续、可比、实际观察三层筛选，报告复发分子／观察分母及观察覆盖。无后续暴露时复发数和率为 null；实现测试 passed 与 operational validation 分开，均不能证明收益归因。
- **替代解释**：相关任务没有再出现、难度下降、运行时或规则版本变化、失败签名漂移都可能解释“未复发”。
- **SYSTEM**：优先保留有真实暴露检验的修复；无验证时记录缺口，不继续堆规则。
- **USER**：在下一项同类任务使用已有修复，不为了制造样本读取私密历史；提供实际出现的问题与既有验证指针。
- **验证／证伪**：预先约定可比暴露、失败签名和回滚条件；复发或质量／安全退化时重新调查并按授权回滚，不以一次单测替代运行证据。

## 6. 委派收益

- **问题**：委派结果是否被采用并通过验证，协调与合并返工是否抵消收益？
- **证据**：既有 actor Token、任务包、停止条件、产物验收、采用／未采用与合并返工证据。当前没有结构化采用率和关键路径时只做有来源的定性分析。
- **可计算与边界**：可报既有 Token 比例，不把它叫速度提升或成本浪费。并行时间不得相加；没有依赖时序与可比串行基线，不计算加速比。
- **替代解释**：独立审查的安全收益、难题选择偏差、缓存与模型版本会改变代价。
- **SYSTEM**：只对独立且可验收的证据面委派，缩小任务包和回包；保留必要独立 reviewer。
- **USER**：说明委派的独立验证目标或交付边界，不以代理数量作为完成标准。
- **验证／证伪**：同复杂度比较质量、采用结果和关键路径；合并返工上升或失去独立审查时撤回该拆分。

## 7. 上下文与规则负担

- **问题**：哪些载入或恢复与后续重复工作、约束丢失具有直接关联证据？
- **证据**：Phase 1 的发生身份、载入覆盖、兼容 Token 口径、压缩与恢复回执，以及后续同任务验收或返工指针。
- **可计算与边界**：可报已有计数、缺口与兼容占比；恢复字段已核验不证明随后行为正确。当前不自动建立压缩到返工的因果连接，不从模型名猜 Token 口径。
- **替代解释**：必要跨 epoch 重读、任务复杂度、长产物与外部错误都可能同时增加上下文及返工。
- **SYSTEM**：有证据后才把主技能细节移到按需引用；保留必读约束和恢复关键字段。
- **USER**：提供当前最小目标、有效授权、已验收产物及下一步；无需反复贴整段历史，也不跳过必读材料。
- **验证／证伪**：比较同类任务后续约束遵守与验收；规则缩短导致遗漏时回滚，不以 Token 降低抵消质量下降。

## 8. 改进实验

- **问题**：下一项最小改变预计影响哪个结果，什么证据会推翻它？
- **证据**：一项主要变化、比较条件、版本／cohort、任务结果、介入／返工注释、维护后续观察、质量与安全门。
- **可计算与边界**：结构化部分可复算；实验因果、优先级及替代解释保持人工判断。没有比较条件时仅作观察，不输出统一绩效分、ROI 或普遍性结论。
- **替代解释**：选择偏差、熟悉度、模型更新、外部负载、任务难度与观测缺失须分别列明。
- **SYSTEM**：一次改一个主要因素，使用现有建议 manifest 关联证据，保留修改前恢复点。
- **USER**：选择一个重复出现且有明确验收的工作场景；预先约定停止条件，不为实验扩大历史读取权限。
- **验证／证伪**：同时比较目标结果与质量／安全护栏；暴露不足就保持未知，护栏失败、效果反向或比较条件失效时停止并按授权回滚。

## 交付接口

报告按 report-template.md 的六个结果问题先交付结论，再按八个视角展开证据；行动步骤见 [IMPROVEMENT.md](IMPROVEMENT.md)。审计者只从经入口验证、出处已核验的显式证据填入原有模板；report_pair 不消费 `collaboration_analysis` 自动生成结论，成对提交合同不变。旧聚合 JSON 验证器不认证该扩展及保存后的篡改。缺少对应字段或 `analysis_version` 时显示不可用；不要把注释数、来源指针存在或实现单测成功写成维护收益。
