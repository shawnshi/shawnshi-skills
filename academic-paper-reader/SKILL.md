# 学术论文深度拆解

## 先确认任务合同

1. 识别用户真正要完成的任务：判断是否值得读、理解机制、准备组会、评估可信度、准备复现、模拟审稿或支持业务决策。按该任务组织输出，不机械复述论文目录。
2. 识别输入形态：本地 PDF、其他全文文件、可访问链接、DOI、标题、粘贴正文或仅有摘要。
3. 确定交付档位：
   - **快速问答**：回答一个明确问题，或在只有摘要时做“摘要级初筛”。默认直接在对话中回答，不加载完整模板，不生成文件。
   - **标准拆解**：阅读一篇完整论文，建立证据索引并审查方法、结果和局限。用户要求“深入分析”但未要求引用演化或复现时默认采用此档。
   - **深度溯源**：处理正文加多个附录、代码与数据复现、严格基线比较、前后向引用演化或版本差异。
4. 只在缺失信息会改变论文身份、档位或结论时提问。若必须确认联网范围、保存位置和交付形式，合并成一次询问。

## 锁定论文身份与证据范围

1. 在分析前记录标题、作者、年份、发表场所、DOI/arXiv/其他标识、实际分析版本和访问日期。标题检索出现多个合理候选时先消歧；不要静默把用户指定版本替换为另一版本。
2. 区分预印本、会议版、期刊版、修订版、勘误和撤稿状态。可信度判断或高风险应用必须检查公开可得的更正、撤回及版本差异；无法联网时明确标为未核验。
3. 对 PDF 或附件先建立资产清单：正文、参考文献、表格、图片、公式、附录、补充材料、试验注册、代码和数据。检查页数、章节连续性和文本提取质量。
4. 遇到扫描件、双栏错序、乱码或表格公式丢失时，使用当前环境可用的 PDF 提取、页面渲染或 OCR 能力交叉核对。无法可靠恢复时停止对受影响部分作确定性判断。
5. 只有摘要时允许输出摘要级初筛，但必须在标题和结论旁明确标注“未读取全文”，不得评价完整实验设计、未展示结果或完整局限。
6. 需要完整的来源处理和证据规则时读取 [resources/source_evidence_protocol.md](resources/source_evidence_protocol.md)。

## 按研究类型选择审查框架

先识别主要研究类型，再读取 [resources/study_type_guides.md](resources/study_type_guides.md) 中对应部分。不要用统一的 baseline、消融或 SOTA 框架套所有论文。

- 机器学习与计算机研究；
- 临床试验；
- 观察性与因果研究；
- 诊断、预后与医学 AI；
- 系统综述与 Meta 分析；
- 定性研究；
- 数学与理论研究；
- 实验科学与工程研究。

混合研究分别审查各部分，再说明证据如何汇合。无法可靠分类时说明原因，采用最保守的通用证据审查，不假装套用专业框架。

## 一次建立文档地图与证据索引

1. 全文只做一次基础提取，建立章节边界、表图清单、关键主张、数字、数据来源、比较对象和引用列表。
2. 为关键结论维护证据索引，至少记录：
   - 编号；
   - 主张；
   - 类型：作者明示事实、论文数据支持的推断、分析者判断、外部证据或未确认；
   - 定位：页码、章节、表、图、公式、附录或外部链接；
   - 支撑内容或数字；
   - 判断与置信度。
3. 对样本量、效应值、置信区间、P 值、单位、相对/绝对变化、训练成本和基线结果做两次独立核对。若正文、图表和附录数字冲突，保留冲突，不替作者调和。
4. 比较模型、干预或基线时核对数据、样本、预算、预处理、指标、评估集和统计口径是否一致。不同条件下的结果不得直接表述为优劣。
5. 明确记录代码、数据、附录、关键对照、注册方案或复现细节缺失造成的残余不确定性。

## 审查证据，不替论文背书

1. 检查研究问题与指标是否对应，设计能否识别作者声称的关系，结论是否超过数据支持范围。
2. 区分统计显著性、效应大小、实际意义和外部适用性。高风险医疗、公共卫生或政策场景优先说明人群、效应、不确定性、安全性和适用边界；不要把论文拆解当作临床或政策建议。
3. 区分作者自述局限和分析发现的额外局限。对额外局限使用“可能、提示、无法排除”等与证据强度匹配的语言。
4. 只有用户明确要求模拟审稿时使用 accept、reject 或评分标签；否则评价证据强度和需要补充的验证。
5. 不复制大段论文正文或整幅受版权保护的图表。以转述和位置锚点为主，短引文仅在措辞本身需要分析时使用。

## 控制深度溯源和并行成本

1. 用户明确要求“引用演化、前作、后续研究、最新进展或联网核验”即视为相应范围的联网授权。否则只检索目标论文及完成身份、版本、勘误或撤稿核验所必需的公开资料；扩大范围前一次性确认。
2. 深度溯源默认先筛选不超过 12 个候选节点，深读不超过 5 篇，前向和后向各追踪一层。任务明显需要更大范围时说明增量成本并调整，不让引用网络无限扩张。
3. 只有至少存在两个可独立证据流时才使用子代理，例如方法审查、结果核对、复现资产和引用演化。先向各任务提供共享文档地图和相关分片，不让每个任务重复阅读全文。
4. 主代理统一论文身份、术语、证据编号和比较口径；对子任务冲突回查原文，不以多数意见代替证据。
5. 未发表、保密或可能包含患者/个人信息的材料默认不联网扩散，也不向非必要子任务分发；先说明限制并在本地材料范围内完成。

## 解释核心机制

1. 先准确解释机制，再决定是否使用类比或贯穿案例。只有教学式解释确有帮助时读取 [resources/storytelling_manual.md](resources/storytelling_manual.md)。
2. 明确标注“论文中的实际案例”和“仅用于解释的类比”，并说明类比失效的边界。
3. 只在信息流、因果链、结构差异或演化关系用文字难以看清时绘图。优先使用当前宿主可渲染的表格、流程图或 Mermaid；普通终端再使用简洁 ASCII。

## 形成交付物

按用户任务裁剪，标准或深度报告通常包含：

1. 一句话结论和证据边界；
2. 论文身份、版本及阅读范围；
3. 研究问题、核心机制与贡献；
4. 研究类型与方法审查；
5. 关键结果、数字及比较条件；
6. 证据索引；
7. 局限、隐藏前提和复现风险；
8. 用户场景下的意义与不可据此得出的结论；
9. 深度档的演化链、外部来源范围和残余不确定性。

需要完整报告时读取 [resources/template.md](resources/template.md)。模板是可裁剪清单，不是固定章节协议。

## 选择保存位置并避免副作用

1. 用户指定文件名或位置时优先遵守。
2. 当前宿主提供持久化文件库或标准工件位置时，默认保存到该位置；不要为了询问本地目录而阻塞已经可以完成的分析。
3. 用户明确要求与本地源文件同目录保存且目录可写时，使用 `<原文件名去扩展名>_论文拆解.md`。
4. 只在用户要求文件、但当前宿主没有默认持久化位置时，一次性询问可写目录。URL、DOI或粘贴正文任务若未要求文件，直接在对话中交付。
5. 目标文件已存在时，先确认它属于同一来源和版本；归属不清时使用带时间戳的新文件名，不覆盖。
6. 写入前记录本地源文件 SHA-256；写入采用当前环境支持的安全编辑方式，绝不修改源论文。

## 运行确定性门禁

保存标准或深度 Markdown 后运行：

```bash
python scripts/paper_audit_gate.py REPORT.md --mode standard
```

先把脚本解析为本技能目录下的实际路径，不要假定当前工作目录就是技能目录。

本地源文件任务同时传入 `--source-path`、写入前记录的 `--source-sha256`，必要时传入 `--expected-output-dir`。深度报告使用 `--mode deep`。可用 `--json`返回结构化验证证据。

门禁只判断文件、编码、未处理标记、必要证据章节、路径和哈希等确定性问题；论文身份是否正确、方法是否支持结论、证据定位是否准确仍需人工复核。门禁失败时修复后重跑，不把警告伪装成通过。

最终回复说明：一句话结论、实际分析版本、全文/摘要范围、联网范围、文件位置（如有）、门禁结果、输出与源文哈希证据，以及仍未解决的不确定性。
