# 标题、案例与机制表达

这些方法只改善理解效率，不是报告结构或学术质量判据。证据准确、来源可回查和用户任务始终优先。

## 1. 标题

标题优先说明研究对象、主要干预或机制和结论强度。无法兼顾简洁与准确时，保留论文原题或准确术语，用副标题解释。

自查：

- 是否能识别研究对象和主要变化；
- 是否把相关性写成因果、把单数据集结果写成普遍规律；
- 是否使用“颠覆、碾压、彻底解决、首次证明”等超出证据的词；
- 是否错误翻译人名、方法名、数据集或量表。

## 2. 案例和类比

只有机制抽象且用户需要教学式解释时才使用贯穿案例。统计审查、复现清单、系统综述、理论证明或用户要求简洁时通常不需要。

必须标注案例类型：

- **论文实际案例**：来自论文实验、病例、数据或材料，并给出位置；
- **解释性类比**：由分析者构造，只帮助理解，不是论文证据。

类比应逐项对应输入、机制、约束和输出。至少说明一个失效边界，避免把类比中的关系误当成真实因果。

## 3. 公式

公式对理解、审查或复现必要时保留，并说明：

- 每个关键符号代表什么；
- 公式依赖哪些假设；
- 改变一个变量会产生什么影响；
- 论文是否用数据或证明支持该关系。

面向非技术读者时，可先给直观解释，再把推导放入附录；不要为了易读删掉决定结论成立的条件。

## 4. 机制图

仅在关系明显比线性文字更易读时绘图，例如多阶段信息流、因果链、模型结构差异或研究演化。

- 宿主支持渲染时使用小型表格、流程图或 Mermaid；
- 普通终端使用宽度受控的 ASCII；
- 图中只放有证据支持的实体和关系；
- 外部溯源关系标注“直接继承、修正、反证、复现或仅主题相关”。

## 5. 表达强度

把表达强度与证据对应：

| 证据状态 | 建议表述 |
|---|---|
| 直接由论文数据或证明支持 | “结果显示”“定理证明” |
| 支持但存在重要限制 | “在该样本和设定下支持” |
| 分析者合理推断 | “提示”“可能”“与……一致” |
| 信息不足 | “无法判断”“尚未核验” |
| 外部证据冲突 | “现有结果不一致”，并分别定位来源 |
