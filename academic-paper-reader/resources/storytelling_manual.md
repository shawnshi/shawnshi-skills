# 标题与故事弧：可选写作方法

这些方法用于改善可读性，不是报告结构、发布门禁或学术质量判据。技术准确性、证据边界和用户任务优先于文风。

## 1. 标题写作

标题应让读者快速识别研究对象和主要变化。可以采用凝练中文，也可以保留准确的英文术语、论文原题、人名或产品名。无法兼顾凝练和可识别性时，优先准确，并用副标题补充解释。

**可选自查**

- 是否说清论文研究什么，而不是只追求警句感？
- 是否保留了不能可靠翻译的术语？
- 是否把结论强度写得超过论文证据？

**表达示例**

| 论文核心思想 | 直述标题 | 凝练标题 |
|---|---|---|
| 奖励信号把模型锁在已会轨迹里，擦掉题目就解锁 | 奖励信号会把模型锁死在已会的轨迹里 | 学会，反成枷锁 |
| 只用错样本做 RL，反思能力自己长出来 | 只用错样本做 RL，反思能力自己长出来 | 错处长出反省 |
| 模型在向量空间里思考比生成 token 更省更准 | 模型在向量里想，比一边想一边写更省 | 默想胜出口 |
| 多智能体缺的是组织协调而非个体智能 | 多智能体协作受组织方式限制 | 多智不如善织 |
| 写作时预测剩余长度让模型知道何时收尾 | 模型每写一个 token 就估计离收尾还有多远 | 知止方能落笔 |

如果凝练标题会造成误解，改用直述标题，或增加副标题，例如 `#+subtitle: 把“还要写多远”做成一个 value 函数`。

## 2. 故事弧与贯穿案例

当论文机制抽象、用户需要教学式解释时，可以用同一个案例贯穿问题、旧方法、转折、解法和结果。综述、复现实验、统计审查或用户要求简洁时，不必使用故事弧。

- **问题**：用具体例子说明旧方法在哪里失效。
- **转折**：说明新方法改变了哪个机制或约束。
- **解法与结果**：回到同一例子，展示变化及其证据。
- **类比**：只有在映射关系可靠时使用，并明确类比不能覆盖的部分。
- **公式**：公式对理解或复现必要时保留，同时解释符号、假设和直观含义；面向非技术读者时可将细节移至附录。
- **概念数量**：只拆解支撑当前解释所需的概念，不设固定数量。
