# 来源与证据协议

用于全文、附录和多来源材料的证据控制。目标是让每个关键判断可回到确定版本、确定位置和确定数字；不重复主技能的分析与叙事流程。

## 1. 论文身份与版本锁定

开始摘录前创建唯一的来源卡，不凭文件名猜测论文身份。

- 记录规范标题、作者、发表载体、年份和稳定标识符，如 DOI、PMID、预印本编号或注册号。
- 记录当前材料类型：预印本、投稿稿、作者接受稿、正式发表版、校样、勘误、撤稿说明或补充材料。
- 记录版本日期、版本号、获取日期、来源 URL 或本地路径；本地文件可加哈希以识别后续替换。
- 查明是否存在更新版本、勘误、表达式关注或撤稿；若不能联网，只标记“未核验”，不要假定不存在。
- 多个版本并存时选择主版本并说明理由；其他版本只用于差异核对，不混合页码和数字。
- 正文、补充材料、注册、方案、统计分析计划、代码和数据分别赋来源 ID，并记录彼此关系。
- 身份无法唯一确认时停止强结论，先解决同名论文、早期版本或会议/期刊重复发表问题。

推荐最小来源卡：

| 字段 | 内容 |
|---|---|
| `source_id` | 稳定短标识，不随文件名变化 |
| `identity` | 标题、作者、载体、年份、标识符 |
| `version` | 材料类型、版本日期/号、状态 |
| `retrieved` | 获取日期、URL 或本地路径 |
| `integrity` | 哈希或其他文件指纹，可选 |
| `relations` | 附录、方案、勘误、代码、数据的来源 ID |

## 2. PDF 与材料完整性

不要把“能搜索到文字”等同于“已取得完整正文”。

### 文件级检查
- 核对封面标题、作者、页数、正文起止、参考文献末页及文件是否截断、加密或损坏。
- 对照目录、文内引用和发布页，列出应有的图、表、附录、补充文件、视频、代码或数据附件。
- 逐项标记已取得、缺失、无法打开或版本不明；关键附件缺失时降低结论置信度。
- 若 HTML、PDF 和补充文件内容不同，保留各自来源 ID，不静默拼成一个“全文”。

### 版面与提取检查
- 双栏 PDF 先抽查阅读顺序；警惕跨栏串行、脚注插入正文、页眉页脚污染和断词。
- 扫描件先判断 OCR 覆盖率；抽查专有名词、负号、小数点、上下标、希腊字母和表格数字。
- 图像型表格不要只依赖 OCR；放大查看表头、跨列标题、单位、脚注和符号定义。
- 公式需同时核对视觉版和上下文；确认分子分母、求和范围、条件、上下标及编号引用。
- 图需核对坐标轴、尺度、截断、误差线含义、图例、面板标签和样本量；颜色不可作为唯一辨识线索。
- 附录中的排除规则、超参数、额外终点和稳健性分析应纳入文档地图，不能视为次要材料自动跳过。
- 提取工具失败时记录失败位置并改用视觉读取或人工转录；不要用猜测补齐乱码。

## 3. 证据索引

每个承重结论至少建立一条证据记录。索引服务于核验，不要求把所有背景句都结构化。

| 字段 | 填写要求 |
|---|---|
| `claim` | 报告中准备表达的单一、可检验主张 |
| `evidence_type` | 直接陈述、原始数据、图表、推导、作者解释、外部来源 |
| `locator` | 来源 ID + 页/节/段 + 表/图/公式/附录编号，能精确回到原处 |
| `quote_or_data` | 必要的短原文，或带单位、分母、时间窗的数据 |
| `assessment` | 支持、部分支持、反驳、仅背景；同时说明限制或冲突 |
| `confidence` | 高/中/低，并给出版本、完整性、测量或推断层面的理由 |

索引规则：

- 一条记录只承载一个主张；复合主张拆开，避免某一引用只支持半句话。
- 区分作者声称、数据直接显示、分析者重算和跨来源推断，不把后两者伪装成原文。
- `locator` 优先使用稳定结构编号；页码依赖版本时同时写章节、表图或段落线索。
- 引文只保留核验所需的最短片段；数据摘录必须保留表头、单位、组别和脚注条件。
- 同一主张存在相反证据时并列记录，不能只保留支持项；在 `assessment` 中解释取舍。
- 缺少直接证据时写“未定位到”，不要用作者摘要、新闻稿或二手解读补成确定结论。
- 置信度评价的是这条证据对该主张的支撑强度，不是论文整体声望。

示例骨架：

```yaml
- claim: "干预在 12 周降低主要结局"
  evidence_type: "原始数据"
  locator: "S1, p.8, Table 2, primary outcome"
  quote_or_data: "组别、分母、效应值、区间、单位"
  assessment: "部分支持：有组间差异，但失访不平衡"
  confidence: "中：正式版本；缺失数据假设影响结果"
```

## 4. 数字双核对

关键数字指影响摘要结论、比较、风险判断或可复现性的数值。

### 第一次核对：忠实转录
1. 从主来源读取数值，并同时记录单位、分母、人群、组别、时间窗和统计口径。
2. 核对负号、小数位、百分比与比例、均值与中位数、标准差与标准误、区间上下限。
3. 追踪表格脚注、图注、缺失值规则、调整模型和分析集；禁止只抄孤立单元格。

### 第二次核对：独立验证
1. 从另一呈现位置复查，如正文对表格、图对补充表、摘要对主要结果；不要复制第一次笔记。
2. 可重算的派生数字写出公式、输入值和舍入规则；确认分母与原分析一致。
3. 检查效应方向、区间是否包住零值/无效值、百分数之和、样本流和事件数是否自洽。
4. 若两处冲突，以原始层级更高、定义更完整的材料为主，并在索引中保留冲突，不擅自平均。

至少对以下内容双核对：主要效应、关键基线、样本量、事件数、失访、性能差异、安全信号及结论依赖的派生值。无法完成第二次核对时明确标记“单次读取”，并降低置信度。

## 5. 外部溯源边界

- 默认只用用户提供的论文及其随附材料；扩大检索前遵守用户授权和主技能的联网边界。
- 为确认身份、版本、勘误或撤稿状态而做的最小核验，也要记录外部来源和访问日期。
- 外部资料只能承担其直接支持的角色：定义、方法背景、前作、后续复现或版本状态。
- 不用后续论文替原论文补写缺失方法，不用评论文章替原始数据证明结果。
- 外部来源与论文来源分别编号；报告中明确哪些判断超出目标论文本身。
- 优先稳定的一手材料：出版记录、注册、方案、数据/代码仓库和被引用原文；二手来源只作导航。
- 付费墙、登录或不可访问内容只能标记存在，不能据摘要或搜索片段推断全文细节。
- 若溯源发现与目标论文冲突，呈现冲突、版本与日期，不静默改写目标论文的主张。

## 6. 共享文档地图与分片

仅在长论文、多附件或并行阅读确有收益时建立共享地图。

### 文档地图
为每个来源 ID 记录：页码范围、章节、表图公式、附录、关键主题、提取状态、负责人和已知缺口。地图是定位层，不承载最终结论。

### 分片原则
- 优先按可独立证据问题分片，如“方法与样本”“主要结果”“附录稳健性”，而非机械等分页。
- 给每片明确输入来源 ID、边界、应返回的证据索引字段和禁止外推的范围。
- 相邻片保留少量重叠，覆盖跨页表格、章节开头、图注和续表；重叠项标记为待去重。
- 所有参与者使用同一术语表、版本锁和文档地图，不各自改写变量名或合并版本。
- 分片产物优先返回定位和证据记录，不直接提交互不衔接的长篇叙述。
- 汇总者核对遗漏、重复、矛盾、跨片依赖和置信度，再统一结论；不得以多数票消解证据冲突。
- 敏感材料在未授权时不得交给外部服务或子代理；无法保证边界时由主流程本地处理。

## 7. 引用预算

引用预算关注证据密度和可核验性，不设机械条数。

- 优先引用改变结论的主张：核心结果、关键限制、版本状态、重要比较和外部事实。
- 一条来源可支持相邻的同一主张，但不能挂在包含多个未被支持断言的长段末尾。
- 对目标论文内部证据给精确定位；对外部来源给稳定链接、标题或标识符和访问日期。
- 直接引语保持最短；优先准确转述并保留定位，遵守来源与平台的引用长度限制。
- 表格、图和附录可直接作为证据位置，不必为了“更多引用”寻找二手复述。
- 常识性过渡句不需引用；分析者判断需标成判断并指出依赖的证据，而非伪造权威背书。
- 交付前抽查每个承重引用：是否真的支持紧邻主张、是否版本一致、是否能被读者访问或定位。

## 8. 敏感与未发表材料

- 未发表稿、审稿材料、内部数据、患者材料和受限附件默认按非公开材料处理。
- 未获明确许可，不上传到外部网站、不扩大联网检索、不转交外部人员或不受控代理。
- 仅在任务所需范围内读取与摘录；证据索引避免复制身份信息、密钥、隐私字段和可重识别组合。
- 需要示例时做最小化脱敏，并标记哪些字段已改写；不要让脱敏示例反向成为事实证据。
- 未发表结论标记为“未公开/待核验”，不能用公开论文语气包装，也不能生成虚假的公共引用。
- 保存、共享和删除临时材料时遵守用户指定位置、保留期与访问范围；边界不明先询问。
- 对潜在研究不端、安全或隐私风险，只报告可见证据与不确定性，不扩散原始敏感内容。

## 9. 输出存储适配

- 先确定用户是否要求文件。只需对话答复时直接交付，不把选择目录设为分析前置条件。
- 用户指定位置优先；未指定且需要文件时，使用当前宿主提供的持久化文件库或标准工件位置，不猜测私人知识库。
- 只有用户明确要求与本地来源同目录保存且目录可写时，按主技能命名规则保存；原 PDF、附件、代码和数据保持只读。
- URL、DOI 或粘贴文本没有来源目录时，不臆造“同目录”。宿主没有默认持久化位置且用户要求文件时，再一次性询问可写目录；临时分析区不冒充长期存储。
- 目标已存在时先核验归属与版本；不确定则使用新文件名，不静默覆盖。
- 敏感材料不得因默认持久化、共享或同步规则而越过用户授权；发生冲突时先停止并说明。
- 使用 UTF-8 和可移植文件名；证据索引可嵌入报告或另存结构化文件，但两者应共享来源 ID。
- 保存后重新读取文件，检查非空、路径、版本信息、引用定位、未处理占位符和关键章节。
- 最终交付说明实际文件、验证结果、缺失附件、单次读取数字、外部来源与其他残余不确定性。
