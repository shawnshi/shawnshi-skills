# 复盘结构参考

本文件提供可裁剪的复盘结构，不是固定章节协议。选择与用户问题和现有证据有关的部分；没有数据的部分标为“数据缺口”或直接省略。

## 最小结构

```markdown
# [时间范围] Audit

## 时间范围与证据
- [材料、来源、覆盖窗口和缺口]

## 关键事实
- [事实与证据位置]

## 判断与替代解释
- **判断:** [由事实支持的有限判断]
- **证据强度:** [高/中/低及理由]
- **替代解释:** [不能排除的因素]

## 下一步
1. [触发条件、最小动作、完成标准]
```

## 承诺对照表

只在存在用户明确承诺及对应证据时使用。

```markdown
| 承诺 | 状态 | 证据 | 外部约束或未知 |
|---|---|---|---|
| [承诺] | [完成/部分完成/未完成/无法判断] | [证据] | [说明] |
```

## 日程与能量管理背景

- 默认只读获取复盘周期内的日历与 Garmin 数据；当前周期末端数据不新鲜时，可按主技能的新鲜度门启动一次已授权同步任务。其他来源只使用用户提供或当前任务明确授权的内容，并写明实际覆盖窗口与同步结果。
- 日历能证明安排，不能单独证明出席、完成或真实投入。
- 健康指标用于描述同期背景，不从单个指标推断疾病、人格、动机、认知或职业表现，也不建立确定因果。
- Garmin 本地 `partial` 保留使用并记录缺口；受控任务同步失败不重试也不实时回退，只有本次未尝试新鲜度同步、本地明确 `no_data` 且本次已授权联网时，才允许一次同窗口云端只读回退。登录、令牌写入、注册或修改任务、直接运行同步脚本及其他来源仍需另行授权。

使用健康数据时采用下列稳定结构；没有健康数据时可整节省略并在“数据缺口”中说明。

```markdown
## 能量管理（描述性生理背景）
- **数据范围与来源:** [请求窗口、实际观测窗口、本地/实时来源]
- **组件覆盖与新鲜度:** [sleep/hrv/body_battery/heart_rate/stress 的状态、最近观测日期和缺口]
- **采集审计:** `sync_eligible=<true|false>; sync_attempted=<started|waited_existing|not_attempted>; task_status=<终态|not_checked>; local_reread=<accepted|rejected|not_run>; local_status=<complete|partial|no_data|read_error|not_run>; live_fallback=<used|not_used>; reason=<稳定原因码>`
- **睡眠观察:** [时长及状态、深睡/REM 占比、躁动、观测日期；无数据写“无有效观测”]
- **HRV 与静息心率观察:** [值、Garmin 原始状态、各自观测日期；不生成诊断]
- **Body Battery 与压力观察:** [充入量/峰值/低值、日均压力、各自观测日期]
- **执行带宽:** `not_scored`；[说明不从健康指标生成认知、职业表现或日程承载评分；主观状态如有则另列来源]
- **睡眠负债:** [来源提供时写 sleep_debt_h、sleep_debt_status=provided_by_source、method、baseline_h 和 window_days；未提供时写 sleep_debt_h=null、sleep_debt_status=not_provided_by_source、method=none、baseline_h=null、window_days=null 及原因]
- **摩擦解构:** [分列已记录负荷、主观感受、生理观测、外部约束和未知项，不使用未经证实的机制标签]
- **交叉归因:** [只描述时间共现、日期错位和替代解释，不写因果或能力推断]
- **干预指令:** [可选；写触发条件、最小动作和完成标准，由用户结合主观状态决定]
- **数据缺口与不可判断事项:** [缺失、日期错位、来源限制、趋势资格]
```

字段语义、来源状态和周期资格以 [energy_management.md](energy_management.md) 为准。

## 可执行动作

每个动作尽量包含：

- 触发条件；
- 最小下一步；
- 完成标准；
- 依赖或阻塞；
- 复核日期（仅在用户需要时）。

不要求固定数量、SMART 套话或动作化标题。行动质量由证据适配性和可执行性人工判断。

## 可选交接

只有用户明确要求保存或交给 `personal-diary-writer` 时，才按 [handoff_contract.md](handoff_contract.md) 生成载荷。先展示报告和目标位置；载荷本身不授权写入。
