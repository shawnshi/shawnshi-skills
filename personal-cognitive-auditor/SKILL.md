# 认知与执行复盘

## 工作流程

1. 确认复盘周期、目标和可用材料。默认只读获取该周期内的日历事件与 Garmin 健康摘要，不再为这两类读取单独询问授权；其他私人来源仍需用户在当前任务中明确授权。没有数据时列出缺口，不补造事实。
2. 日历只读取与周期相关的事件、时间和必要描述，不创建、修改、删除或回复事件；日程只能证明安排，不能单独证明出席或完成。
3. Garmin 优先读取本地数据；本地缺失或不完整时，可使用已有有效凭证进行云端只读查询。若需要重新登录、写入或更新令牌、下载原始活动文件、同步或改写本地数据库，必须另行取得明确授权。
4. 按“事实—解释—影响—下一步”分离信息。区分可控行为、外部约束和证据不足项，避免把复杂结果简化为人格判断。
5. 对照用户明确承诺，标记“完成、部分完成、未完成、无法判断”，并引用对应证据。
6. 按证据量识别值得报告的重复模式，说明证据强度和可能的替代解释。不要把推测写成结论，也不为满足固定数量补写模式。
7. 提出少量可执行动作；每个动作写明触发条件、完成标准和最小下一步。健康信号只作描述性背景，不从单次指标推断疾病、因果或治疗方案。
8. 仅当材料规模大且可以独立拆分时使用子代理做交叉核对。不要让子代理接触超出任务所需的私人数据。
9. 仅在用户明确要求保存时，调用合适的日记或记忆流程；先展示拟保存内容和目标位置，再执行持久化。

## 输出

按需使用以下结构，不强制填充无数据章节，也不要求固定标题：

- 时间范围与证据来源
- 关键事实
- 承诺对照表
- 重复模式与替代解释
- 风险或数据缺口
- 下一步行动

保持直接、克制和具体。可以指出矛盾，但不得羞辱、辱骂或假装掌握用户动机。健康相关动作只能作为一般生活建议；出现危险症状或持续异常时，建议联系合格医疗人员。

## 资源

- 需要日、周、月或年度模板时，读取 `prompts/` 下对应文件；模板继承日历与 Garmin 的默认只读授权，但不扩大到其他私人数据源。
- 需要字段含义或交接格式时，按需读取 `references/templates.md`、`references/semantic_layer.md` 或 `references/handoff_contract.md`。
- 生成文件草稿后，可运行 `python scripts/audit_gate.py <draft_file>`。若草稿直接来自本技能模板，加 `--enforce-template-fields`，此时模板占位符和已出现的 Handoff Payload Schema 错误会阻断；自由文本中的相似符号只作提示。若脚本不可用，人工检查模板字段、交接字段、证据引用和未证实判断。

## 边界

- 默认只读获取复盘周期内的日历与 Garmin 数据；只取完成当前复盘所需的最小字段和时间范围。
- 不自动读取历史对话、私人日志目录、邮件或全局记忆。
- 默认授权不包含日历写操作、Garmin 登录或令牌持久化、原始活动文件下载、本地数据库同步或任何第二处持久化。
- 不把复盘结论写入日记、知识库或其他长期存储，除非用户明确授权。
- 不把日程安排当作实际出席证据，不把健康指标相关性写成医学诊断、人格定性或确定因果。
- 不输出隐藏推理过程；只呈现证据、判断和不确定性。
- 不因追求强硬语气而忽略客观原因、数据质量或安全风险。

## 验证分层

- 硬错误：文件缺失或不可读、正文为空、显式模板模式下仍有未处理模板字段、已提供 Handoff Payload 但 JSON 或必填字段不符合 `references/handoff_contract.md`。
- 软提示：章节缺失、术语空泛、语气过度、没有量化或没有健康/日程数据。
- 人工判断：模式是否由证据支持、替代解释是否充分、行动是否适合用户、是否存在医学或人格越界。
