# 认知与执行复盘

## 最短用法：生成不等于保存

- 只生成：`复盘今日日志，只读，不同步` 或 `本周个人日志审计，草稿`。按已有材料生成复盘并披露缺口。当用户要求草稿、预览、只读或不保存时，保持只读，不写入 canonical 目标，也不触发新鲜度同步。
- 生成并申请 canonical 保存：受保护用户事件中的精确 `本周个人日志审计`（月、季度仅使用第 9 步既有精确请求）。不是所有“周结”“复盘”或等价生成意图都能通过保存门；不得把修饰请求改写成精确请求，也不扩大授权词或周期范围。
- 最短校验链：读取对应模板 → 生成临时草稿 → `python scripts/audit_gate.py <draft_file> --enforce-template-fields --period-type weekly --period-id <YYYY-Www>` → 经日记权威门生成 scope 与绑定的 `periodic-audit-request-v1` approval → 对应 `replace-weekly-audit` → 写后校验。月、季度使用其既有周期 ID 与动作。内容门通过不等于保存授权；不得直接写 canonical 或另存第二处。
- 缺少健康数据时可如实降级为事实与数据缺口，不补造数值或完成状态；模板模式仍须填写能量管理稳定字段及不可用原因，不能删节规避内容门。健康读取失败不授权绕过请求、权威、范围或保存门；脚本不可用时人工检查只支持草稿交付，不替代自动保存门。
- 周期写入保留结束日既有日记与其他周期区块，只替换目标同周期 H2；日记后续使用 `replace-personal-diary` 更新正文时也保留同日合法周/月/季区块。重复或非法周期区块失败关闭，不使用整日 `replace-date` 代替周期保存。

## 工作流程

1. 确认复盘周期、目标和可用材料。默认只读获取该周期内的日历事件与本地 Garmin 健康摘要，不再为这两类本地读取单独询问授权；用户明确要求“个人日志周审计”“本周个人日志审计”或等价任务时，还授权通过 `personal-diary-writer` 权威门只读提取该自然周的 canonical 个人日志日期块。联网读取和其他私人来源仍需用户在当前任务中明确授权。没有数据时列出缺口，不补造事实。
2. 日历只读取与周期相关的事件、时间和必要描述，不创建、修改、删除或回复事件；日程只能证明安排，不能单独证明出席或完成。
3. Garmin 读取先通过 canonical `personal-health-analysis` 的 `runtime-authority.json` 与权威门，再遵循其授权和失败关闭合同。先在同一解释器内预检并读取精确复盘窗口。若复盘窗口包含当前自然日、任一必需组件的最近观测早于窗口末日，则本次复盘请求授权在分析前直接运行一次两阶段同步（`sync_health_data.py sync --dry-run` 后 `--allow-network --allow-sync`）：
   - 同步命令显式携带 `--allow-network --allow-sync --allow-health-data`；任何授权或绑定漂移都停止触发。
   - 完成后核对计划绑定、`database_fingerprint_changed=true`、请求末日和逐组件末端覆盖，再重新执行本地读取；同步状态文件或退出码本身不证明成功，进程提前终止仍归类 `interrupted_or_terminated`。
   - 限流、认证、超时、计划绑定、完整性或覆盖验证失败时不得在同一次复盘中重试；继续使用原有本地证据并将同步状态写入数据缺口。不得改走实时接口或备用来源。
   - 历史窗口不含当前自然日，或者用户要求草稿、预览、只读、不同步或不联网时，不触发同步；也不得自动注册、更新或修复任何计划任务。
   同步完成后的本地结果按状态处理：`complete` 使用本地结果，`partial` 保留本地结果并披露缺口。只有本次未尝试新鲜度同步、本地明确为 `no_data`、用户本次已授权联网且实时预检通过时，才允许一次同窗口、同组件的云端只读回退；一旦同步已尝试，失败或覆盖不合格都结束本次采集分支。Schema、完整性、数据库变化或读取错误不得触发回退。审计技能不得登录、写令牌、下载原始活动。
4. 按“事实—解释—影响—下一步”分离信息。区分可控行为、外部约束和证据不足项，避免把复杂结果简化为人格判断。
5. 对照用户明确承诺，标记“完成、部分完成、未完成、无法判断”，并引用对应证据。
6. 按证据量识别值得报告的重复模式，说明证据强度和可能的替代解释。不要把推测写成结论，也不为满足固定数量补写模式。
7. 提出少量可执行动作；每个动作写明触发条件、完成标准和最小下一步。生成“能量管理（描述性生理背景）”时，必须为“采集审计、执行带宽、睡眠负债、摩擦解构、交叉归因、干预指令”分别生成非空内容；采集审计必须披露同步资格、是否启动/等待、任务终态、本地重读、实时回退及原因码，字段语义和不可用状态按 `references/energy_management.md` 投影。执行带宽与睡眠负债不得出现任何 `[DATA_UNAVAILABLE]`，包括占位符后附解释的形态；执行带宽固定使用 `not_scored` 且不得含 score/value/level/color，睡眠负债必须满足数值、状态、方法、基线和窗口的跨字段约束。个人日记历史标题 `能量管理 (Biological-Cognitive Correlation)` 仅作为 Gate 兼容别名；新草稿统一使用中文标题和同一稳定字段集。健康信号不得生成能量、恢复力、准备度或执行带宽总分，不得据此推断认知或职业表现、确定因果，或替用户决定训练、会议和重要事项。
8. 仅当材料规模大且可以独立拆分时使用子代理做交叉核对。不要让子代理接触超出任务所需的私人数据。
9. 个人周、月、季度审计通过 `audit_gate.py` 的内容门与周期标题拓扑门后，默认自动保存到 `personal-diary-writer` 返回的 canonical 季度个人日志。自动保存只接受受保护用户事件中的精确 canonical 请求：`本周个人日志审计`/`个人日志周审计`、`本月个人日志审计`/`个人日志月度审计`、`本季度个人日志审计`/`个人日志季度审计`，或包含周期 ID 的 `AUDIT_AUTOSAVE` 结构化命令；可带单一 `[OVERRIDE]` 或 `[WARROOM]` 前缀。任何额外修饰都不自动写入，因此草稿、预览、只读或不保存请求必然失败关闭。调用层必须生成 `periodic-audit-request-v1` artifact，绑定受保护用户事件 ID 与文本 SHA-256、周期、动作、canonical 目标、scope hash 和 `canonical_autosave` 策略。保存只新增或替换周期结束日中的同周期 H2 审计区块；payload 的第一个非空行且唯一 H2 必须是目标周期标题，其余标题只能为 H3 或更深；0–3 个空格缩进的 ATX H1/H2 与 Setext H1/H2 同样禁止。日期块不存在时只创建日期标题与该审计区块。任何审计门、权威门、请求门、范围门或写后校验失败都停止保存，不得直写文件或转存到第二处。日度、年度、自定义路径及交接仍须另行明确授权。

## 输出

按需使用以下结构，不强制填充无数据章节，也不要求固定标题：

- 时间范围与证据来源
- 关键事实
- 承诺对照表
- 重复模式与替代解释
- 风险或数据缺口
- 下一步行动

保持直接、克制和具体。可以指出矛盾，但不得羞辱、辱骂或假装掌握用户动机。健康相关动作只能作为一般生活建议；出现危险症状或持续异常时，建议联系合格医疗人员。

## 资源

- 需要日、周、月、季度或年度模板时，读取 `prompts/` 下对应文件；模板继承日历与 Garmin 的默认只读授权，但不扩大到其他私人数据源。周、月、季度模板同时定义 canonical 自动保存封套，必须完整遵循。
- 出现 Garmin、能量管理、健康背景或趋势判断时，必须读取 `references/energy_management.md`；需要通用字段含义或交接格式时，再按需读取 `references/templates.md`、`references/semantic_layer.md` 或 `references/handoff_contract.md`。
- 生成文件草稿后，必须运行 `python scripts/audit_gate.py <draft_file>`。若草稿直接来自本技能模板，加 `--enforce-template-fields`；模板占位符、能量管理字段缺失或内容为空、以及已出现的 Handoff Payload Schema 错误都会阻断。自由文本中的相似符号只作提示。若脚本不可用，必须人工检查模板字段、交接字段、证据引用和未证实判断。

## 边界

- 默认只读获取复盘周期内的日历与本地 Garmin 数据；只取完成当前复盘所需的最小字段和精确时间范围，不为满足趋势算法自动扩大窗口。
- 不自动读取历史对话、邮件或全局记忆；只有明确的个人日志周审计允许经权威门读取当前自然周的 canonical 日期块，不得扩展到其他周或其他私人目录。
- 默认授权不包含任意联网、日历写操作、Garmin 登录或令牌持久化、原始活动文件下载、注册或修改同步任务、直接运行同步脚本或任何第二处持久化。唯一例外是第 3 步的新鲜度门：可直接运行一次两阶段同步。`activities` 与 `training_load_series` 也不属于默认能量管理组件。
- 个人周、月、季度审计只在受保护结构化请求门通过后写入 canonical 季度个人日志；草稿、预览、只读、“不保存”或其他修饰请求不得写入。其他复盘、知识库、Vector Lake、外部系统或第二处持久化仍需单独明确授权。
- 不把日程安排当作实际出席证据，不把健康指标相关性写成医学诊断、人格定性、认知或工作能力判断、确定因果。
- 不输出隐藏推理过程；只呈现证据、判断和不确定性。
- 不因追求强硬语气而忽略客观原因、数据质量或安全风险。

## 验证分层

- 硬错误：文件缺失或不可读、正文为空、显式模板模式下缺少可识别的能量管理章节或仍有未处理模板字段、能量管理五项稳定投影缺失或只有空占位状态、执行带宽或睡眠负债暴露 `[DATA_UNAVAILABLE]`、执行带宽出现评分/等级字段、睡眠负债的值/状态/方法/基线/窗口不一致、已提供 Handoff Payload 但 JSON 或必填字段不符合 `references/handoff_contract.md`、数值型自造能量/准备度/执行带宽总分、把缺失健康值写成 0、显示 Python `None`、未提供来源却生成睡眠负债、由 `partial` 触发云端回退、强制训练或日程指令。
- 软提示：章节缺失、术语空泛、语气过度、没有健康/日程数据、健康因果或医学/认知/职业表现越界风险。
- 人工判断：模式是否由证据支持、替代解释是否充分、行动是否适合用户、不同指标日期是否被误写成同日快照、共享上游信号是否被重复计权。
