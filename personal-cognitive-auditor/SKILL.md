# 认知与执行复盘

## 工作流程

1. 确认复盘周期、目标和可用材料。默认只读获取该周期内的日历事件与本地 Garmin 健康摘要，不再为这两类本地读取单独询问授权；用户明确要求“个人日志周审计”“本周个人日志审计”或等价任务时，还授权通过 `personal-diary-writer` 权威门只读提取该自然周的 canonical 个人日志日期块。联网读取和其他私人来源仍需用户在当前任务中明确授权。没有数据时列出缺口，不补造事实。
2. 日历只读取与周期相关的事件、时间和必要描述，不创建、修改、删除或回复事件；日程只能证明安排，不能单独证明出席或完成。
3. Garmin 读取遵循当前 `personal-health-analysis` 的授权和失败关闭合同。先在同一解释器内预检并读取精确复盘窗口。若复盘窗口包含当前自然日、任一必需组件的最近观测早于窗口末日，且用户此前已经启用的 `Codex-Garmin-Health-Sync` 任务存在、启用并仍绑定当前健康技能运行器，则本次复盘请求授权在分析前启动该任务一次：
   - 启动前核对任务为当前用户、`RunLevel=Limited`、`LogonType=Interactive`、`MultipleInstances=IgnoreNew`，动作仍显式携带 `--allow-network --allow-sync --allow-health-data`；任何身份或动作漂移都停止触发。
   - 任务已在运行时只等待同一实例，不再启动第二个实例；完成后必须核对脱敏状态、数据库指纹变化和同窗口本地覆盖，再重新执行本地读取。状态文件或退出码本身不证明成功。
   - 限流、认证、超时、计划绑定、完整性或覆盖验证失败时不得在同一次复盘中重试；继续使用原有本地证据并将同步状态写入数据缺口。不得改走实时接口或备用来源。
   - 历史窗口不含当前自然日，或者用户要求草稿、预览、只读、不同步或不联网时，不触发任务。任务不存在或未启用时不得自动注册、更新或修复。
   同步完成后的本地结果按状态处理：`complete` 使用本地结果，`partial` 保留本地结果并披露缺口；只有明确 `no_data`、用户本次已授权联网且实时预检通过时，才允许一次同窗口、同组件的云端只读回退。Schema、完整性、数据库变化或读取错误不得触发回退。审计技能不得登录、写令牌、下载原始活动或直接调用同步脚本绕过已授权任务。
4. 按“事实—解释—影响—下一步”分离信息。区分可控行为、外部约束和证据不足项，避免把复杂结果简化为人格判断。
5. 对照用户明确承诺，标记“完成、部分完成、未完成、无法判断”，并引用对应证据。
6. 按证据量识别值得报告的重复模式，说明证据强度和可能的替代解释。不要把推测写成结论，也不为满足固定数量补写模式。
7. 提出少量可执行动作；每个动作写明触发条件、完成标准和最小下一步。存在健康数据并生成“能量管理（描述性生理背景）”时，必须为“执行带宽、睡眠负债、摩擦解构、交叉归因、干预指令”分别生成非空内容；字段语义和不可用状态按 `references/energy_management.md` 投影。执行带宽与睡眠负债不得出现任何 `[DATA_UNAVAILABLE]`，包括占位符后附解释的形态；执行带宽固定使用 `not_scored` 且不得含 score/value/level/color，睡眠负债必须满足数值、状态、方法、基线和窗口的跨字段约束。个人日记历史标题 `能量管理 (Biological-Cognitive Correlation)` 仅作为 Gate 兼容别名；新草稿统一使用中文标题和同一稳定字段集。健康信号不得生成能量、恢复力、准备度或执行带宽总分，不得据此推断认知或职业表现、确定因果，或替用户决定训练、会议和重要事项。
8. 仅当材料规模大且可以独立拆分时使用子代理做交叉核对。不要让子代理接触超出任务所需的私人数据。
9. 个人周审计通过 `audit_gate.py` 后默认自动保存到 `personal-diary-writer` 返回的 canonical 季度个人日志，除非用户明确要求草稿、预览或不保存。若用户要求草稿、预览或不保存，则保持只读，不写入或归档。原始周审计请求即为这一个 canonical 目标的保存授权，不再要求二次确认；月度、年度、日度复盘及自定义路径仍须用户明确要求保存。自动保存必须把周审计嵌入周期结束日的现有日期块：保留当天日记正文，只新增或替换同一 `[YYYY-Www] Weekly Cognitive Audit` 标题块，再用 `diary_ops.py scope` 与 `replace-date` 原子替换整个日期块。任何审计门、权威门、范围门或写后校验失败都停止保存，不得直写文件或转存到第二处。

## 输出

按需使用以下结构，不强制填充无数据章节，也不要求固定标题：

- 时间范围与证据来源
- 关键事实
- 承诺对照表
- 重复模式与替代解释
- 风险或数据缺口
- 下一步行动

保持直接、克制和具体。可以指出矛盾，但不得羞辱、辱骂或假装掌握用户动机。健康相关动作只能作为一般生活建议；出现危险症状或持续异常时，建议联系合格医疗人员。

## 资源

- 需要日、周、月或年度模板时，读取 `prompts/` 下对应文件；模板继承日历与 Garmin 的默认只读授权，但不扩大到其他私人数据源。周模板同时定义 canonical 自动保存封套，必须完整遵循。
- 出现 Garmin、能量管理、健康背景或趋势判断时，必须读取 `references/energy_management.md`；需要通用字段含义或交接格式时，再按需读取 `references/templates.md`、`references/semantic_layer.md` 或 `references/handoff_contract.md`。
- 生成文件草稿后，必须运行 `python scripts/audit_gate.py <draft_file>`。若草稿直接来自本技能模板，加 `--enforce-template-fields`；模板占位符、能量管理字段缺失或内容为空、以及已出现的 Handoff Payload Schema 错误都会阻断。自由文本中的相似符号只作提示。若脚本不可用，必须人工检查模板字段、交接字段、证据引用和未证实判断。

## 边界

- 默认只读获取复盘周期内的日历与本地 Garmin 数据；只取完成当前复盘所需的最小字段和精确时间范围，不为满足趋势算法自动扩大窗口。
- 不自动读取历史对话、邮件或全局记忆；只有明确的个人日志周审计允许经权威门读取当前自然周的 canonical 日期块，不得扩展到其他周或其他私人目录。
- 默认授权不包含任意联网、日历写操作、Garmin 登录或令牌持久化、原始活动文件下载、注册或修改同步任务、直接运行同步脚本或任何第二处持久化。唯一例外是第 3 步的新鲜度门：可启动一次用户此前已经启用且身份核验通过的 Garmin 自动同步任务。`activities` 与 `training_load_series` 也不属于默认能量管理组件。
- 个人周审计默认只写入 canonical 季度个人日志；草稿、预览或“不保存”请求不得写入。其他复盘、知识库、Vector Lake、外部系统或第二处持久化仍需单独明确授权。
- 不把日程安排当作实际出席证据，不把健康指标相关性写成医学诊断、人格定性、认知或工作能力判断、确定因果。
- 不输出隐藏推理过程；只呈现证据、判断和不确定性。
- 不因追求强硬语气而忽略客观原因、数据质量或安全风险。

## 验证分层

- 硬错误：文件缺失或不可读、正文为空、显式模板模式下缺少可识别的能量管理章节或仍有未处理模板字段、能量管理五项稳定投影缺失或只有空占位状态、执行带宽或睡眠负债暴露 `[DATA_UNAVAILABLE]`、执行带宽出现评分/等级字段、睡眠负债的值/状态/方法/基线/窗口不一致、已提供 Handoff Payload 但 JSON 或必填字段不符合 `references/handoff_contract.md`、数值型自造能量/准备度/执行带宽总分、把缺失健康值写成 0、显示 Python `None`、未提供来源却生成睡眠负债、由 `partial` 触发云端回退、强制训练或日程指令。
- 软提示：章节缺失、术语空泛、语气过度、没有健康/日程数据、健康因果或医学/认知/职业表现越界风险。
- 人工判断：模式是否由证据支持、替代解释是否充分、行动是否适合用户、不同指标日期是否被误写成同日快照、共享上游信号是否被重复计权。
