## 排序与稳定连接

先处理已证实的安全／质量损害或副作用未知，再看有暴露证据的重复摩擦；证据不足时优先补核当前来源，不凭 Token 排名或虚构维护 ROI。只选一个主要实验，其余留作候选，不为对称结构强行提出 SYSTEM 和 USER 各一项。

发现沿用 F-xx，建议沿用 canonical manifest 的 R-xx；同一编号的含义、层级与所有者不得静默改变。建议的动作、所有者、状态和验证字段只在 manifest 维护，MD/HTML 由同源生成；以下动作卡是正文解释，不是新 Schema、第二个建议表或采集格式。方向实质变化时新建建议并按既有合同显式关闭旧项，不让旧编号消失。

## 一张动作卡

- **连接与优先级**：F-xx → R-xx；影响、直接观察的代价、证据强度与可逆性；不能排序则说明缺口。
- **问题／暴露证据**：来源指针、已声明与已核验出处、根任务与失败签名；任务、介入、返工各自有效／已知／未知分母，修复版本及 cohort 的暴露／可比后续／实际观察分母。未提供就写未知。
- **假设机制**：哪一项局部机制可能导致问题，至少一个替代解释；不写人格、动机或因果定论。
- **最小改变与所有者**：SYSTEM 是有边界的技能／编排／运行时修复，由对应维护者负责；USER 是可复用的输入／验收实践，由使用者选择。分清责任，不把系统缺陷转嫁给用户重复解释。
- **预期方向与护栏**：一个目标结果的预期方向；原验收、权限、隐私与安全门保持不变，不编造收益数字。
- **同类比较与混杂因素**：固定任务类型、复杂度、版本、数据可得性、权限及质量门；记录模型变化、熟悉度、负载和样本选择。不可比就只观察，不宣称因果。
- **停止／回滚／证伪**：提前写明护栏失败、效果反向或可比条件失效时停止；SYSTEM 仅在既有授权内恢复原版本，USER 恢复原实践。若需要新的写入权限则停在回滚动作前补足授权。暴露不足保持未知，不判成功。
- **后续状态**：区分建议实施状态、实现测试、运行验证、复发观察与假设结论。无可比后续暴露时复发数／率不可计算；单测通过或一次未复发不证明维护价值。

## 假设示例：避免重复授权而不删除授权门

以下全部是假设，不是本用户历史，也不是实测收益。假设已提供的 `synthetic:10-12` 经人工核对，显示同一目标、范围和副作用下再次要求批准，形成 F-01 → R-01；SYSTEM 候选为仅修复该调用的授权续接，所有者为该组件维护者。机制假设是续接未保留有效范围，替代解释是载荷已变化；USER 不需要为此反复粘贴历史。

下一项唯一实验是在一项同类型本地可逆任务中验证这个局部修复：预期重复批准减少，原验收和授权边界不变。比较原版本同类任务并核对复杂度与模型版本；加入目标不变、范围变化和副作用未知的验证情境。若漏问实质变化、发生越界或验收退化，立即停止，按已有授权恢复原版本并撤回有效性判断。当前仅是假设计划，暴露分母未知、运行验证未执行、收益未知；不新增采集。

## Token 改进候选与验证

用量分析的工作分类、证据链和候选故障见 [TOKEN-ANALYSIS.md](TOKEN-ANALYSIS.md)。在主要问题摘要中连接 F-xx → R-xx，再使用本文件动作卡；不要把消耗排行直接变成整改命令。

对可核验的重复读取、同签名无效重试、返工或委派冗余，选择一项最小变化。模型路由建议必须有同工作类型、相近难度、同版本与采样口径的质量／时间对照；缺证据时不直接建议换廉价模型或减少独立审查。比较 Token 与任务验收、错误率和用户介入，节省但质量下降、工作转交用户或授权门弱化时停止。相关用量区间重叠时，不累计多条建议的“节省总量”。
