# 医疗与 AI 合规复核规则

本文件用于识别问题、记录依据和决定何时升级，不给出法律、临床或器械分类结论。法规、标准、产品分类和监管状态必须按适用地区与信息截止日核验原文。

## 必需上下文

开始实质复核前至少记录：

| 字段 | 最低要求 |
|---|---|
| 适用地区与信息截止日 | 涵盖部署地、数据所在地、服务对象所在地和可能的跨境目的地 |
| 决策主体与预期用途 | 谁采购、建设、运营或销售；系统用于行政辅助、临床支持、科研还是直接诊疗 |
| 使用者与影响对象 | 医务人员、患者、研究受试者、未成年人或其他脆弱群体；影响范围和严重度 |
| 数据上下文 | 数据类型、敏感性、来源、目的、处理阶段、授权基础、保存期限、共享对象和跨境路径 |
| 临床与人工边界 | 是否影响诊断、治疗、处方、分诊或资源分配；人工复核、覆盖和降级机制 |
| 技术与运行边界 | 部署方式、外部模型或云服务、关键接口、安全等级、日志、灾备和事件响应 |
| 产品与研究状态 | 预期用途、产品分类/注册或备案待核验项，以及是否涉及科研、伦理或数据二次使用 |
| 采购和合同状态 | 验收、SLA、责任、赔偿、知识产权、数据返还/销毁、退出迁移和分包边界 |

缺少适用地区、预期用途、关键数据类型或临床影响时，不得给出实质性“合规/不合规”判断。可以继续制作问题清单，但成果成熟度应标为 `blocked` 或最多 `working_draft`，并列出补充责任人。

## 复核维度

- 数据处理：目的限定、最小必要、合法/授权基础、访问控制、留存、共享和跨境条件；
- 网络与系统安全：安全分级、供应链、身份权限、日志、灾备、漏洞和事件响应；
- 算法与模型：训练与评测数据、适用人群、偏差、漂移、可解释性、版本控制和人工复核；
- 医疗器械与临床边界：预期用途、诊疗影响、产品分类、注册/备案和上市后监测；
- 研究伦理：受试者、病历回顾、知情同意、伦理审批、二次使用和结果发表；
- 采购与合同：验收口径、服务边界、分包、责任、SLA、知识产权、退出和数据迁移。

## 必须升级的情形

出现以下任一情形时，停止自行下结论，并把具体问题、证据 ID 和决策截止日升级给相应专业人员：

| 触发情形 | 至少升级给 |
|---|---|
| 系统可能直接影响诊断、治疗、处方、分诊，或缺少有效人工复核/降级路径 | 临床安全负责人；必要时医疗器械/法规专业人员 |
| 产品分类、注册/备案、临床评价或研究与医疗服务边界不明确 | 法务/法规与伦理专业人员 |
| 患者敏感数据用于训练、二次使用、外部模型服务、跨机构共享或跨境处理 | 数据保护、法务和安全负责人 |
| 涉及未成年人、遗传信息、罕见病、精神健康等高敏感或脆弱群体 | 伦理、临床和数据保护负责人 |
| 发现或合理怀疑数据泄露、关键系统安全事件、不可接受的业务连续性风险 | 安全与事件响应负责人；按组织流程上报 |
| 合同包含无限责任、难以验收的结果承诺、异常赔偿、数据无法返还或高锁定风险 | 法务、采购/商务和业务责任人 |
| 适用规则冲突、关键原文无法获取或事实仍有重大争议 | 对应地区的合格法律或行业专业人员 |

升级不是默认否决。未经具名专业人员确认，不得将待复核事项写成“已合规”“无需注册”或“法律风险可接受”。

## 输出字段

| 合规项 ID | 风险点 | 适用地区 | 当前依据及日期 | 关联证据 ID | 事实状态 | 信息缺口 | 建议升级对象 | 下一验证点/责任人 | 处置状态 |
|---|---|---|---|---|---|---|---|---|---|

可以确定性检查引用、日期、字段和占位符；对实质适用性只给出人工复核标记。严重度和发生概率应分开记录，不能用总分自动接受高严重度风险。
