# 医疗数字化投资优先级与 ROI/TCO 模型

仅在任务涉及项目排序、预算、商业模式、产品投资或投标决策时读取本文件。模型用于暴露假设和取舍，不替代患者安全、监管、财务、采购或法务审批。

## 一、投资优先级

### 1. 先过门禁

以下门禁不能被综合高分抵消：

- **强制义务门禁**：存在有原文、适用地区、责任主体和截止日支持的法律、监管、审计、合同或业务连续性义务；
- **临床安全门禁**：当前风险可能造成不可接受的患者伤害，且已有事件、流程或专业评估证据；
- **合规门禁**：关键数据、产品分类、伦理、网络安全或跨境问题需要专业确认；
- **可交付门禁**：缺少负责人、关键资源、基础数据、技术前置条件或最低运行保障；
- **财务/现金门禁**：超出批准预算、现金承受能力或厂商可接受的营运资金上限；
- **合同门禁**：验收、责任、SLA、知识产权、退出或回款条件不可接受。

门禁结果使用 `pass`、`conditional`、`fail`、`unknown`。`unknown` 不等于 `pass`。对强制和安全事项可以“必须处理”，但仍应比较修复路径、范围和时序，而不是自动批准任一指定产品。

### 2. 再做可解释排序

在通过或有条件通过门禁的方案中，可按 0—5 分比较以下七项。权重由决策主体在看到结果前确认；若未确认，使用等权或只展示维度，不生成“客观总分”。

| 维度 | 0 分 | 3 分 | 5 分 |
|---|---|---|---|
| 强制项 `M` | 无适用义务 | 有明确政策/合同驱动但时限宽松 | 有约束性义务、明确责任和近期截止日 |
| 临床安全 `S` | 无可识别影响 | 可降低中等风险，有基线待验证 | 处理有证据的高严重度当前风险 |
| 战略一致性 `G` | 与批准战略无关 | 支持一个重要目标 | 直接支撑核心业务目标且有管理层责任人 |
| 可量化价值 `V` | 收益只是口号 | 部分基线和兑现路径明确 | 基线、目标、归因、兑现责任和下行情景完整 |
| 准备度 `R` | 无负责人/流程/数据 | 主要条件具备，仍有可控缺口 | 业务、数据、技术、治理和采用条件已验证 |
| 资源可行性 `C` | 预算或关键产能不可得 | 资源可调配但有明显挤占 | 预算、人员和运维能力已落实，机会成本可接受 |
| 依赖可控性 `D` | 关键前置条件未知或不可控 | 依赖明确且有缓解计划 | 依赖少或已完成，回退路径清楚 |

若使用权重，`priority_score = Σ(weight_i × score_i)`，权重之和为 1。每个分值必须引用证据/假设 ID、评分责任人和置信度。总分只用于排序讨论，门禁、资源冲突和项目间依赖仍需单独决策。

## 二、模型输入

### 1. 必须建立的基线

- 基线期间、适用组织/人群、样本量和数据源；
- 当前流程、服务量、质量/安全、时间、收入、成本和资源占用；
- 不投资时的反事实，包括自然增长、政策变化、既有改造和价格变化；
- 目标状态、采用率爬坡、观察期和归因边界；
- 名义币种、是否含税、价格年度、折现率及其批准/假设来源。

没有基线或反事实时，不得把前后差异全部归因于项目。

### 2. 全生命周期成本

至少检查：

- **CapEx/一次性投入**：软件或产品研发、实施、接口、数据清理与迁移、基础设施、安全、验证/注册、培训与替班、项目管理、停机切换、双轨运行、应急准备；
- **OpEx/经常性投入**：许可/订阅、云与算力、运维、数据治理、模型监控、质控、客服、升级、漏洞修复、审计、供应商管理和持续培训；
- **风险与退出**：延期/超支准备、质保/SLA赔付、返工、数据返还、替换迁移、合同终止和残值；
- **内部资源**：临床、业务、IT、研发、实施和管理投入。即使不产生新增现金，也要记录机会成本和产能影响。

同时给出名义 TCO 与现值 TCO：

```text
nominal_TCO = Σ cost_t
PV_TCO = Σ cost_t / (1 + discount_rate)^t
```

## 三、收益、归因与兑现

收益先分类，再决定是否货币化：

| 类型 | 处理方式 |
|---|---|
| 患者安全、临床质量、公共服务、体验和能力建设 | 单列指标；除非有透明且获认可的方法，不强行折算现金 |
| 成本避免 | 说明若不投资是否真的会发生支出，以及避免支出的预算科目 |
| 生产率/节省时间 | 只有排班、加班、外包、编制或可交付产能发生可验证变化时才计入现金收益 |
| 收入/回款改善 | 扣除增量服务成本、容量限制、支付规则和归因份额 |
| 风险降低 | 可用情景或风险调整值；不能把极低概率重大损失直接写成确定收益 |
| 厂商合同收入 | 与贡献利润、回款现金流、续费和机会成本分开，不等同于价值或利润 |

可现金化收益的一般结构为：

```text
attributable_cash_benefit_t
  = baseline_delta_t × eligible_volume_t × unit_value_t
  × attribution_share_t × cash_conversion_rate_t
```

采用率、实现概率和价格变化应作为显式情景/敏感性变量，避免在不同变量中重复打折。

### 收益实现台账

| 收益 ID | 指标与基线 | 目标/期间 | 数据源 | 归因依据 | 现金化机制/预算科目 | 业务责任人 | 财务确认 | 实际值 | 状态 |
|---|---|---|---|---|---|---|---|---|---|

状态建议为 `hypothesis`、`baseline_validated`、`in_delivery`、`observed`、`realized`、`rejected`。`observed` 的流程改善只有经过现金化机制和财务确认后才能标为 `realized` 现金收益。

## 四、现金流与决策指标

按年度或月度列示，建设期较短或回款节点敏感时使用月度：

```text
net_cash_flow_t = attributable_cash_benefit_t - cash_cost_t
NPV = Σ net_cash_flow_t / (1 + discount_rate)^t
ROI_nominal = (Σ attributable_cash_benefit_t - nominal_TCO) / nominal_TCO
```

- 回收期为累计净现金流首次不小于 0 的时间；跨期插值时公开方法。
- IRR 为使 NPV=0 的折现率。现金流没有合理的正负变化或存在多解时标为 `not_meaningful`，不要强行报告。
- 至少呈现下行、基准和上行情景，并列出对 NPV、现金峰值或结果影响最大的 3—5 个变量。
- 同时报告未折现与折现口径、税费处理、名义/实际价格和残值，避免混算。
- 对强制或患者安全项目，财务 NPV 可以为负；决策仍需说明合规/安全价值、替代方案和最低成本路径。

### 机器可复核的计算契约

需要自动门禁时，不要只保存自然语言公式或汇总数字。Blackboard 中的假设、成本、收益、现金流、公式、情景和输出都使用全局唯一且大小写敏感的稳定 ID；所有引用必须精确指向已存在记录。

- 现金流至少包含 `id`、`period_index`、`cost`、`benefit`、`net` 和 `unit`；`net` 必须等于 `benefit - cost`。分情景现金流再记录 `scenario_id`，同一情景内期间不得重复。
- 折现率作为有 ID 的假设保存，使用小数比率而不是百分数字符串。NPV 公式或情景通过 `discount_rate_assumption_id` 引用它。
- 公式至少包含 `id`、`formula_type` 和 `input_ids`。核心白名单类型为 `tco`、`total_benefit`、`net_benefit`、`roi` 和 `npv`；`expression` 只供人阅读，不会被解析或执行。
- 情景至少包含 `id`、`scenario_type`、`assumption_ids`，并通过 `cash_flow_ids` 或内嵌 `cash_flows` 提供可复算输入。至少保留下行和基准情景；不能只写“收益下降20%”再填一个未经复算的输出。
- 输出至少包含 `id`、`metric`、`value`、`unit`，并按需引用 `formula_id` 和 `scenario_id`。现金流恒等式、TCO、总收益、净收益、ROI 和 NPV 的申报值会与独立复算值比较。

自定义公式、缺少机器可读现金流或只有自然语言情景时，只能标为“未自动验证”并产生警告；严格门禁下不能据此达到 `decision_ready`。默认计算容差为金额绝对值0.01、比率绝对值0.000001、百分比0.05个百分点和相对值0.000001；只有在币种单位或披露精度确有需要时才显式调整 `validation_tolerance`，不得用宽容差掩盖模型错误。

## 五、买方与卖方模型

### 医疗机构/买方

除财务指标外，必须并列：患者安全/质量结果、公共服务能力、员工负担、业务连续性和战略目标。内部时间节省不自动等于减员收益。采购价只是 TCO 的一部分，接口、数据、基础设施、双轨运行、培训和退出成本不能遗漏。

### 医疗 IT 企业/卖方

至少计算：

```text
contribution_if_won = contract_revenue - direct_delivery_cost - risk_reserve
contribution_margin = contribution_if_won / contract_revenue
pre_bid_expected_value
  = probability_of_win × contribution_if_won
  - bid_cost - opportunity_cost
peak_working_capital = max(negative cumulative project cash flow)
```

并单列收入确认与现金回款、标准产品与定制成本、售前/研发/实施/运维产能、验收节点、质保/SLA、索赔责任、坏账、续费和退出义务。中标概率只适用于投标前资源决策，不应在“中标后项目是否盈利”的模型里再次打折。

## 六、可交付模型检查

模型达到 `decision_ready` 前至少满足：

- 基线、反事实、期限、币种、税费和折现口径明确；
- CapEx、OpEx、内部资源、风险准备和退出成本已检查；
- 每个关键输入都有证据/假设 ID、责任人和敏感性范围；
- 临床/非现金收益与现金收益分开；收益台账包含归因和兑现责任；
- 买方或卖方口径正确，现金流、TCO、NPV/回收期等计算可复核；
- 下行情景没有越过临床、合规、现金、合同或产能门禁；
- 财务、临床、安全、采购或法务等必要专业复核已有记录。
