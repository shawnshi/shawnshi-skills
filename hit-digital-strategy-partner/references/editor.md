# 战略报告编辑规则

本文件用于编辑已经完成证据收集和分析的战略报告。它不设置最低字数、数字数量、反共识数量或固定标题风格。

## 编辑目标

- 保持事实、来源机构主张、模型假设和分析建议之间的边界；
- 删除重复、营销修辞和没有证据的确定性表达；
- 保留公式、单位、时间、地区、来源和适用条件；
- 让管理层可以定位需要决定的事项、负责人、验证点和退出条件。
- 明确报告站在医疗机构/买方还是医疗 IT 企业/卖方一侧；涉及双方时不混用价值、成本和责任口径。

## 编辑流程

1. 核对决策问题、决策侧、受众、时间跨度、适用地区、信息截止日和预期用途，没有这些信息时先标为缺口。
2. 对每项关键结论建立回指：
   - 外部事实：来源、发布日期、事件日期、适用地区；
   - 用户数据：文件或字段定位、数据周期；
   - 计算结果：公式、单位、输入变量和情景；
   - 分析判断：证据链、替代解释和置信度。
3. 检查相同指标在不同章节的口径、币种、时间范围和单位是否一致。
4. 对无法核实的数字改为待填变量或显式假设，不用“行业常识”补全。
5. 涉及投资时核对基线、CapEx/OpEx、现金流、折现口径、收益归因与兑现机制；医院买方和厂商卖方分别使用 [investment_model.md](investment_model.md) 的审查口径。
6. 检查建议是否包含适用条件、依赖、负责人、验收阈值、整改期和暂停/回退/终止条件。
7. 核对关键结论引用的证据 ID、假设 ID 与模型变量是否存在；冲突证据不得在编辑时被静默删除。
8. 确认成果成熟度后，最后再处理语言、标题、段落和排版。

## 成果成熟度

| 状态 | 可用范围 | 最低条件 |
| --- | --- | --- |
| `working_draft` | 研究和内部讨论 | 决策范围已知；缺口、假设和未核验数字清楚可见 |
| `review_ready` | 跨部门评审 | 关键结论可回指证据 ID；方案、风险和主要变量完整；高影响缺口已分配责任人 |
| `decision_ready` | 提交有权主体拍板 | 门禁已处理；基准/下行情景及敏感性已核对；责任、验收、兑现、退出和需要拍板事项完整；必要的临床/财务/合规专业复核已有记录 |
| `approved_for_execution` | 进入组织批准的执行流程 | 只能记录有权主体、批准日期、范围和附带条件；技能不得自行赋值 |
| `blocked` | 不得据此作出目标决定 | 缺少会实质改变结论的上下文、数据或专业复核，且无法通过明确假设安全前进 |

成熟度取整份成果中最弱的关键链路。`decision_ready` 不等于“建议正确”或“已获批准”。报告使用独立行 `Maturity: decision_ready`、`成熟度：decision_ready` 或两列成熟度表行声明实际状态；frontmatter 中同名字段也计入。所有这些权威声明必须与 Blackboard 一致，重复一致值可接受，未知值或冲突值阻断。围栏代码、缩进代码和 Markdown 引文仅作示例，不作为批准声明；实际批准不得藏在示例里。

## 分层检查

### 确定性错误

- 未处理占位符；
- 缺失必需字段、来源定位或公式变量；
- 同一指标的单位、币种或时间范围冲突；
- 编号、链接或结构损坏。
- 关键结论引用不存在的证据/假设 ID，或同一 ID 被重复定义；
- 把未发生的收益、未签署的合同、未获批预算或未完成的专业复核写成事实；
- 将 `working_draft`、`review_ready` 或 `blocked` 成果标成可执行批准件。

这些错误可以阻断交付。自动门禁仅覆盖可解析的字段和引用；“收益已经发生”“已经批准”等叙述是否属实仍须人工核验。

### 报告引用与财务绑定

- 正文显式 `EV-`、`AS-`、`OUT-` ID 必须精确存在于当前 Blackboard 的证据、假设或输出集合；大小写敏感，不以“依据”“测算”等关键词替代 ID 核验。示例代码块与引文不作实际引用。ID 存在不证明来源支持主张，也不证明历史证据仍有效。
- 正式财务指标使用最小结构化引用，例如 `[[output:OUT-B-ROI metric=roi value=50 unit=%]]`。字段顺序固定，值必须为有限数值；ID 指向 `quantitative_model.outputs`，情景由该输出的 `scenario_id` 确定。metric、unit 和 value 与已验证输出对账；ROI 的 ratio 与百分比可换算，容差沿用模型，其他金额不自动换汇。缺少输出记录时先在原模型内补齐，不另建财务状态。
- 只有 Blackboard 达到 `ready` 且绑定通过时才列入 `verified_output_references`。无效或未完成复核的状态不会产生已验证引用。该列表只证明本次输入状态与结构化声明的数值一致性，不证明经济假设成立。
- 普通回执始终披露 `unchecked` 中的 `prose_numbers`、`source_support`、`approval_authenticity`；状态未就绪时另列 `financial_output_references`。散文中的 ROI、金额、比率即使伴随正确 ID，也未自动核对；不能把 `scope: report_and_blackboard` 或退出码 0 当作全文数字、来源真实性或真实批准通过。

### 启发式提示

- 文字可能过长或过短；
- 标题可能不够清晰；
- 段落可能重复；
- 某项建议可能缺少量化；
- 术语或加粗可能过多。

这些只产生提示，不能单独阻断交付。术语建议列入 `advisories`，为兼容原回执也保留在 `warnings`；`--strict` 只阻断 `errors` 和 `blocking_warnings`，不会因忠实引文中的术语单独失败。缺少数量来源线索、决策数据或专业复核等警告仍属于 `blocking_warnings`。是否需要行动式标题、图表或更长解释，由文档类型和受众决定。

### 人工判断

- 证据是否真正支持建议；
- 临床、财务和合规承诺是否可接受；
- 方案是否适配实际工作流和产品能力；
- 对竞争厂商的陈述是否公平、同口径。
- 综合评分是否掩盖强制、临床安全、合规、现金或资源硬门禁；
- 节省时间、活动量和临床改善是否有可审计的现金化或非现金分类；
- 管理层批准是否来自真实有权主体，而非报告自行推断。

## 组装边界

需要合并多个章节时可使用 `scripts/assembler.py`。该脚本只做确定性拼接和结构检查：零章节默认失败、章节顺序必须稳定、正文不得被清洗规则删改，已有文件只有在用户授权并显式传入 `--force` 时才能覆盖。装配成功不能替代编辑判断或成果成熟度判断。

无 Blackboard 的 `brief` 仅可显式使用 `strategy_gate.py --path REPORT --mode brief --textual-only` 检查文本草稿；报告须声明 `working_draft` 或 `review_ready`。输出 `scope: textual_only`，不验证证据、财务、合规或决策就绪度，不得据此放行正式财务交付。该路径拒绝 `--strict`、正式成熟度及其他模式；已有 Blackboard 时仍走原统一门禁，正式交付仍必须严格检查。装配成功不代表门禁通过。
